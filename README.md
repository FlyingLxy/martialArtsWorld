# 泡点江湖

仿 2000 年前后那种**文字江湖聊天室**的多人网页游戏——挂着页面就长功力，一屋子人一边泡点一边胡侃。

那类游戏（「江湖聊天室」／「文字江湖」，1997 年就有了，算是中国网页游戏的鼻祖）的招牌样子：
左上人物状态，左下各处房间和人数，中间大聊天室分上下屏，右边此地人物，底下一排虚拟动作。这里照着还原了一套。

```
┌ 泡點江湖  某某 18级 一方好手 华山派 ──────── 场景 行囊 信箱 同道 玩法 昼夜 离开 ┐
│ 人物状态  │【竹林小径】竹影森森…              │ 此地人物  │
│ (左上表格)│ [竹下盘膝打坐][寻敌][打坐疗伤]    │ 令狐冲 18 │
│           ├───────────────────────────────────┤ 东方不败12│
│ 江湖去处  │ 江湖公共频道（全服聊天·打斗·公告） │           │
│ 客栈    2 │ ＊ 东方不败向令狐冲抱拳一礼…       ├───────────┤
```

## 跑起来

要求 Node 18+，**零依赖**，不用 `npm install`。

```bash
git clone git@github.com:FlyingLxy/martialArtsWorld.git
cd martialArtsWorld
node server.js          # 或者双击「开服.command」
```

开起来后：

- 自己玩：<http://localhost:8080>
- 叫上朋友：开服时会打印局域网地址，也可以随时双击「查地址.command」

给别人的地址有两种，**主机名那个更稳**（IP 是 DHCP 分的，换个网络就变）：

```
http://192.168.x.x:8080             ← IP，会变
http://你的机器名.local:8080          ← 主机名，不会变
```

**连不上最常见的原因是代理**。Clash／Surge 这类工具会把局域网地址也吃掉，尤其当你的网段不在它的例外
列表里（默认例外通常只有 `192.168.0.0/16`，而公司网络常是 `172.16.x.x`）。让对方打开「绕过局域网地址」，
或把自己的网段加进代理例外。另外确认系统防火墙没拦。

改端口：`PORT=9000 node server.js`。

### 存档

所有人共用服务端的一个 `data.json`（**已在 .gitignore 里，别提交**），每人的角色按**名号 + 暗号**独立，
换台机器换个浏览器，用同样的名号暗号登录就接着玩。名号不存在时前端会先问一句「要新建吗」，
免得老玩家打错一个字以为存档没了。

写盘是**原子**的：先写 `data.json.tmp` 并 fsync，再 rename 顶替，同时把上一份留成 `data.json.bak`。
断电或 `kill -9` 都不会写出半截文件；主文件真坏了，下次开服会自动认出来并从 `.bak` 恢复。最坏丢 30 秒进度。

暗号只存 sha256，但局域网里走的是 HTTP 明文，**别用你在别处用的密码**。

## 这是个什么游戏

**泡点**是核心：到了能修行的地方**自动开始**，每两秒长一次经验，页面开着就一直涨，关掉就停
（当年就是这个规矩，所以房间里才总有人）。打架时自动停，打完自动接着泡。

| 去处 | 修行 | 门槛 |
|---|---|---|
| 悦来客栈 | 在客栈打杂听闲话 | 1 级 |
| 竹林小径 | 竹下盘膝打坐 | 5 级 |
| 后山瀑布 | 立于瀑下练功 | 15 级 |
| 本门后山 | 面壁参悟本门心法 | 30 级 |
| 塞北风雪谷 | 踏雪立桩 | 45 级 |
| 西域星宿海 | 观星吐纳 | 60 级 |

等级超出场地门槛越多收益衰减越狠（最低剩两成半），所以到点就得挪窝。

其余：3 级后拜入五派之一（**入了不能改**），每派 8 门武功带各自路数（少林护体、武当反弹、峨眉连击、
丐帮破防、华山必中）；打怪掉装备和打造材料；**打造**要银子加材料，+9 封顶；社交有三个聊天频道、
悄悄话、8 种虚拟动作、切磋押注、成亲（夫妻同处泡点 +10%）；一个人在线也有事做——衙门悬赏、
客栈告示板、离线书信、擂台留影（影子会使你会的武功替你守擂）。

## 代码怎么组织的

```
game-data.js        数据表 + 数值公式（前后端共用，浏览器走 /data.js 拿）
server.js           服务端：游戏逻辑 + HTTP + SSE
public/index.html   客户端：一个文件装下全部界面和交互
solo-单机版.html     早先做的单机版，双击就玩，跟上面三个没有关系
test.js             主链自测，node test.js
```

**`game-data.js` 前后端共用**，所以里面**不能出现任何 Node API**（`require`、`fs`、`process` 都不行）。
它靠结尾一句 `if (typeof module !== 'undefined') module.exports = ...` 兼容两边。

`server.js` 按注释分区，找东西照这个走：

| 行数附近 | 区块 | 装的是 |
|---|---|---|
| 14 | 世 界 | `world` 全局状态、玩家对象、存档读写 |
| 111 | 推 送 | `push` / `toRoom` / `toAll` / `chat` |
| 143 | 状 态 | `stateOf`、`battleView`——**发给客户端的全部数据在这** |
| 230 | 成 长 | 升级、泡点收益、奇遇 |
| 271 | 战 斗 | 招式结算、PvE、切磋、影子 |
| 583 | 泡 点 | `autoIdle` / `startIdle` / `stopIdle` 和每秒 tick |
| 645 | 银两的出路 | 打造、请客、送花、成亲、摆摊 |
| 856 | 一个人也能玩的 | 告示板、书信、悬赏 |
| 992 | 指 令 | `CMD` 对象，**所有玩家能做的事都在这** |
| 1216 | HTTP | 三个接口 + 静态文件 |

## 数据怎么流动

只有三个接口，没有 WebSocket：

```
POST /api/login    {name, pass, create?}  →  {token} | {isNew:true} | {err}
GET  /api/events?token=…                  →  SSE 长连接，服务端单向推
POST /api/cmd      {token, cmd, args}     →  {ok:1}
```

- **客户端只负责渲染和发指令**，所有判定都在服务端。前端传上来的东西一律不可信。
- **服务端每秒给每个在线玩家推一次完整 `state`**（人物、房间、房间里的人、各房间人数、风云榜、战况）。
  简单粗暴但够用：一个玩家一次约 1～2 KB。
- 另外两种消息随时推：`{t:'log'}` 事件文字、`{t:'chat'}` 聊天。都带 `scope`：
  **`pub` 进上屏**（全服公共信息），**`me` 进下屏**（只给自己看）。这是还原当年"分屏"的关键。
- **在线 = SSE 连着**。连接断了就算离线，泡点会停——这是故意的，不然房间里就没人了。

并发方面：Node 单线程，整个服务端只有两处 `await`（都在读请求体），读完之后指令是**一路同步执行到底**的，
所以两条指令不可能交错，不存在数据竞争。存档也是同步写，不会写出撕裂状态。
但**边界判断仍然要自己写对**（比如扣钱前先夹住余额，别扣成负数）。

## 想改点东西

绝大多数改动只动 `game-data.js`。

<details>
<summary><b>加一个新地方</b></summary>

在 `MAP` 里加一条。`exits` 只影响"去往"那行的展示，实际上左下角列表可以直接跳任何地方：

```js
huashan_top:{name:'华山·绝顶', desc:'一线天开，云海在脚下翻涌。',
  exits:['chengnei'],
  hunt:['xuelang','cike'],                        // 能打的怪，可选
  paodian:{act:'临风独立', exp:14, lv:50, tip:'心胸为之一阔'},   // 能泡点，可选
  shop:'city', forge:true, board:true },          // 各种功能开关，可选
```

场景开关一览：`hunt` 寻敌 / `paodian` 泡点 / `shop`（`inn`｜`smith`｜`city`）/ `arena` 擂台 /
`gamble` 赌坊 / `joinsect` 拜师 / `learn` 学艺 / `gang` 械斗 / `pk` 可切磋 / `treat` 请客 /
`forge` 打造 / `market` 集市 / `board` 告示板 / `quest` 接悬赏 / `sectOnly` 仅本门弟子。
</details>

<details>
<summary><b>加一个怪</b></summary>

`MOBS` 里加一条，然后挂到某个场景的 `hunt` 里。掉落档次由 `DROP.tier(lv)` 按等级自动算，不用配：

```js
laohu:{name:'吊睛白额虎', lv:38, hp:2800, atk:200, def:70, exp:4800, gold:2400},
```

寻敌时只会挑 `lv <= 你的等级+4` 的怪，不会让新手撞上越级的。
</details>

<details>
<summary><b>加一门武功</b></summary>

`SKILLS` 里加一条。`eff` 是特色效果，可以叠加：

```js
xxx:{name:'某某掌', sect:'shaolin', lv:35, cost:5000, mp:28, mult:4.0,
     txt:'一掌拍出，气浪翻腾',                    // 战斗日志里的描述
     eff:{pierce:.5, stun:.2}, note:'破防，还有机会震住对方'},   // note 会显示给玩家
```

`eff` 支持：`guard` 护体减伤（配 `turns`）/ `reflect` 反弹 / `double` 连击概率 / `pierce` 无视防御比例 /
`sure` 必中 / `crit` 暴击加成 / `drain` 吸血比例 / `stun` 定身概率 / `heal` 回血比例 / `mp` 回内力比例 /
`dodge` 闪避加成（配 `turns`）。用 `gang: 300` 代替 `cost` 就是要帮贡换的绝学。
</details>

<details>
<summary><b>加一条玩家指令</b></summary>

两步。服务端在 `CMD` 里加一个方法（第一个参数永远是玩家对象）：

```js
CMD.kowtow = (p, a) => {
  if(p.gold < 100) return log(p, '<b class="r">磕头也要钱？你没钱。</b>');
  p.gold -= 100;
  toRoom(p.scene, {t:'log', scope:'pub', cls:'act',
    html:'<span class="act">＊ '+p.name+'当众磕了三个响头。</span>'});
  sync(p);                     // 改了状态记得同步
};
```

客户端某处加个入口：`<a onclick="cmd('kowtow')">磕头</a>`。
</details>

<details>
<summary><b>给客户端加一块界面</b></summary>

`render()` 里有个**缓存 key**，中栏只在 key 变化时才重画：

```js
const key = JSON.stringify([VIEW, R, me.idle&&me.idle.act, ST.pending, me.pot, me.gold, ...]);
if(key !== lastKey){ lastKey = key; $('scene').innerHTML = …; }
```

**新加的状态如果会影响中栏显示，一定要加进这个 key**，否则界面不会刷新——这是最容易踩的坑。
需要每秒都动的东西（倒计时、泡点计时）不要走中栏，单独找个 `id` 每拍更新，参考 `idleTip()`。

新开一个整页视图：写个 `viewXxx()` 返回 HTML 字符串，在 `render()` 的三元链里挂上，
用 `V.set('xxx')` 切过去。
</details>

## 数值公式一览

全在 `game-data.js` 的 `F` 里，调数值只改这一处：

```js
need : lv => 60*lv^1.75 + 40*lv                    // 升级所需经验
maxHp: 60 + 根骨*14 + 等级*16
maxMp: 30 + 悟性*10 + 等级*8
atk  : 6 + 力量*2.2 + 等级*1.6 + 兵器*打造加成
def  : 2 + 根骨*0.8 + 等级*0.9 + 护体*打造加成
dodge: min(35%, 身法*0.8%)                          // 有封顶
crit : min(40%, 3% + 身法*0.5%)                     // 有封顶
idleTick: 场地基础 × max(25%, 1-(等级-门槛)*3.5%) × (1+悟性*2%)   // 每 2 秒一跳
forge: 每级 +12% 属性，费用 (原价*0.6+200)*(n+1)，成功率 95%-9%n，+5 起失败降级
```

四个属性各管一摊：**力量**→攻击；**根骨**→气血和防御；**悟性**→内力和**泡点速度**（唯一影响升级快慢的）；
**身法**→闪避、暴击、切磋先手。

## 跑测试

改完记得跑一遍，**尤其是动了数值或者钱货相关的地方**：

```bash
node test.js
```

它会在系统临时目录里另起一个服务器（独立端口 8199、独立存档），**绝不碰你正式的 `data.json`**，
跑完自己清理。目前 43 项断言，覆盖这条主链：

| 组 | 验的是 |
|---|---|
| ① 登录 | 生名号先问一句、暗号错拒绝、名号+暗号读回同一角色 |
| ② 泡点 | 上线自动开始、涨的量对得上公式、打架停、打完接着泡、主动收功不会自己又开 |
| ③ 打怪 | 连打八场都能正常收场、掉银子掉材料、行囊不越界 |
| ④ 打造 | 银子和材料都扣对、材料不够要拦住且不白扣钱 |
| ⑤ 钱货守恒 | **并发**转账不透支、总额守恒、摆摊成交卖家实收九成 |
| ⑥ 切磋 | 战书带赌注、抽头正好一成、谁都不会被扣成负数 |
| ⑦ 单人内容 | 悬赏写明去哪打几只、告示留得住、**离线的人也能收到信和银子** |
| ⑧ 存档 | 关服落盘、留备份、**主文件写坏后能从备份救回来** |

测试是真会红的——把之前修好的透支 bug 塞回去，第 ⑤ 组立刻报
`✗ 并发转账不会把钱扣成负数　实际：-1`。加新玩法时请顺手补一组，
写法照抄 `test.js` 里的 `Client` 类（`login` / `connect` / `cmd` / `until` / `said`）。

## 已知的坑和还没做的

想认领就开个 issue，或者直接提 PR。

| | 事情 | 说明 |
|---|---|---|
| 数值 | **身法过 74 点就废** | 闪避 44 点封顶、暴击 74 点封顶，而 60 级手里有 256 点可分。力量也单薄（只给攻击）。四项该重新配平 |
| 玩法 | **死亡惩罚太轻** | 只丢一成银子被抬回客栈，越级挑战和押注切磋都不够紧张 |
| 玩法 | **玩家帮派没做** | 现在的"帮派"只是 NPC 械斗的名字，没有玩家自建组织、帮战、帮派仓库 |
| 玩法 | 悬赏一次只能接一桩 | 也没有连续任务或者剧情线 |
| 玩法 | 影子不会成长 | 擂台留影是快照，主人变强了影子还是老样子，得重新留 |
| 体验 | 移动端只是能看 | 窄屏下三栏堆成一列，没认真做过 |
| 体验 | 聊天记录只留 60 条 | 新人进来看不到更早的，只能靠告示板 |
| 工程 | 没有 HTTPS、没有限流 | 局域网自己人玩够用，**别直接挂公网** |
| 工程 | 测试只盖了主链 | `node test.js` 有 43 项，但界面、门派武功效果、成亲、影子还没覆盖 |
| 工程 | 每秒全量推 state | 几十人没问题，上百人要改成增量推送 |

## 一起开发的约定

- **别提交 `data.json`**（已在 `.gitignore`）。里面是玩家存档和暗号 hash。
- 分支：`main` 保持随时能跑。开 `feat/xxx`、`fix/xxx` 分支，PR 过一遍再合。
- 改完先跑 `node test.js`（43 项，约一分钟），再开两个浏览器窗口用不同名号登录，
  手动验证你改的那部分 + 打一场架 + 泡一会儿点。测试没盖到界面，那部分只能靠眼睛。
- **改数值只动 `game-data.js`**，别把常数写死在 `server.js` 里。
- 新玩法的判定**一律放服务端**。客户端传上来的任何东西都当成假的。
- 代码风格跟着现有的来：两空格缩进，中文注释写"为什么"而不是"是什么"，
  游戏内文案用武侠白话，别出现"点击"「按钮」这类现代词。
