# 数据模型与接口契约

前面九份定的是"游戏是什么"。这一份定**"程序怎么存、怎么传"**——
没有它没法开工。

沿用 v1 已验证的架构：**零依赖 HTTP + SSE 推送 + POST 命令**，
存储层可插拔（JSON 文件 / MySQL）。

## 一、存档结构

### 玩家（player）

```js
{
  name, pass, salt,              // 登录，密码按 v1 已有的加盐方案
  lv, exp, need,                 // 等级与经验（need 由曲线算，不存）
  hp, mp, maxHp, maxMp,          // 战斗资源
  attrs: { 力道, 身法, 根骨, 元息 },   // 四维（数值基准 二之三）
  free: 0,                       // 未分配属性点
  sect, sectRank, contrib,       // 门派、职位、帮贡
  talents: { nodeId: rank },     // 天赋树已点节点
  skillProgress: { learned, skillOrder, skillRankPriority }, // 语义见技能进度与等级扩展合同
  gear:  { 武器, 身体, 头部, 腕部, 足部, 佩饰 },  // 六槽，值为 itemId
  bag:   [ item... ],
  silver,
  idle:  { scene, since, last, frac },   // 泡点：frac 是小数余额（v1 教训）
  energy: { cur, cap, last },     // 精力（怪物与掉落 第五节）
  daily: { quest: {done, stock}, dig: {...}, arena: {...} },  // 攒存制
  rep:   { 战力, 名望, 见闻, 家业, 人情 },      // 五条线各自的累计
  titles: [ id... ], titleOn, colorOn, prefixOn,  // 名望展示
  ach:   { id: ts },              // 成就：id → 达成时间戳
  codex: { scene:Set, mob:Set, item:Set, fish:Set, herb:Set, page:Set },  // 见闻
  home:  { ... },                 // 家园
  master, apprentices: [],        // 师徒
  sworn: { id, name, members },   // 结拜
  foes:  [ {name, ts} ],          // 仇人簿（上限 10）
  red:   { val, last },           // 红名
}
```

### 交情：稀疏矩阵，不是玩家属性

```js
// world.bond
{ "甲|乙": { v: 87, last: 1757000000000 } }   // key 为两名字排序后拼接
```

**这是本文最重要的一条结构决定。**
交情是**两人之间**的东西，不属于任何一方。
存成玩家属性会导致双写不一致（甲说 87、乙说 85）。

十来个人最多 45 对，几百条记录，随便存。

### 世界（world）

```js
{
  market: [ {id, seller, item, price, ts, deposit} ],   // 挂单，必须落盘
  mseq,                                                  // 挂单自增号
  rank: { 战力:[], 名望:[], 见闻:[], 家业:[], 人情:[] },   // 五榜缓存
  firsts: { 满级:"某某", 满打造:"某某", 绝境:"某某" },     // 「首个」永久
  chronicle: [ {ts, text} ],                             // 编年史
  elite: { sceneId: nextRespawnTs },                     // 精英刷新表
  rare:  { sceneId: {mobId, until} },                    // 稀有怪当前状态
  boss:  { nextTs },
  hour,                                                  // 时辰（2 小时轮回）
}
```

> **v1 教训**：`market` 只存在内存里，服务器一重启，
> 玩家挂出去的装备永久消失。**挂单、首个记录、编年史必须落盘。**

## 二、SSE 推送：两种包

沿用 v1 已验证的**全量 / 增量分包**（曾把带宽从 9.6 GB/月压到 1.8 GB/月）：

| 包 | 何时发 | 内容 |
|---|---|---|
| `state` | 场景切换、装备变动、等级变化等**结构性变化** | 完整状态 |
| `vitals` | 每 tick | 只有 `hp mp exp silver energy` 等抖动值 |

```js
// 判断是否需要发全量：把抖动字段排除后比较
const JITTER = new Set(['hp','mp','exp','silver','energy','since','last','frac']);
```

### 事件表

| 事件 | 触发 | 谁收到 |
|---|---|---|
| `state` / `vitals` | 见上 | 本人 |
| `chat` | 发言 | 按频道（世界／本地／门派／私聊） |
| `scene` | 有人进出场景 | 同场景所有人 |
| `combat` | 战斗过程 | 本人（**走个人消息，不走公共频道**） |
| `broadcast` | 首领刷新、稀有怪出现、结拜、出师、首个成就 | 全服 |
| `rare` | 稀有怪出现 | **仅该场景在场玩家** |
| `bond` | 交情升档 | 双方 |
| `mail` | 私信、系统通知 | 本人 |

**`rare` 只推给在场玩家**是有意的（[怪物与掉落](怪物与掉落.md)）：
这样才会有人在频道里喊"乱葬岗出稀有了，快来"。
如果全服自动推送，那句喊话就没必要了，社交也就没了。

## 三、命令：POST 一个口子

沿用 v1：所有操作走 `POST /cmd`，`{token, cmd, args}`。

| 分组 | 命令 |
|---|---|
| 登录 | `login` `register` `logout` |
| 移动 | `go(scene)` `idle(on/off)` |
| 战斗 | `hunt` `skill(id)` `flee` `rest` |
| 成长 | `allocAttr(attr,n)` `talent(node)` `forge(slot)` `reroll(slot)` |
| 社交 | `say(ch,text)` `whisper(to,text)` `bond(name)` `nick(name,text)` |
| 师徒 | `apprentice(name)` `guide(name)` `graduate(name)` |
| 结拜 | `swornInvite` `swornAccept` `swornBreak` |
| PVP | `duel(name)` `arena(rank)` `pk(name)` |
| 市场 | `list(item,price)` `buy(id)` `unlist(id)` |
| 任务 | `quest(id)` `submit(id)` `abandon(id)` |
| 家园 | `plant` `harvest` `fish` `smelt` `visit(name)` |
| 展示 | `setTitle(id)` `setColor(c)` `alias(text)` `inscribe(slot,text)` |

**幂等要求**：`forge` `buy` `submit` 这类会改变资源的命令，
必须带客户端生成的 `nonce`，服务端去重——
网络抖动重发不能扣两次钱。

## 四、模块划分

沿用 v1 已有的严格无环依赖，新增模块挂在对应位置：

```
core ← state ← growth ← idle ← social ← combat ← commands ← http
                  ↑        ↑        ↑
              economy   codex    reputation
                          ↑
                        market
```

| 新模块 | 职责 |
|---|---|
| `codex.js` | 见闻自动记录、图鉴完成度 |
| `reputation.js` | 成就判定、称号、五榜计算 |
| `market.js` | 挂单、成交、税、官评价 |
| `bond.js` | 交情累积（含同场泡点计时）、师徒、结拜、仇人 |

`server/check.js` 已有的**跨模块引用与循环依赖检查**要覆盖到新模块。

## 五、定时任务

| 频率 | 做什么 |
|---|---|
| 每 2 秒 | 泡点 tick（含**同场泡点交情计时**） |
| 每 30 秒 | 精英刷新检查、稀有怪出现/消失判定 |
| 每 2 小时 | 时辰轮回、跑商价差刷新、红名衰减 |
| 每天 5 点 | 日常/挖宝/擂台次数发放（**按攒存上限累加，不清零**） |
| 每周一 5 点 | 禁地次数发放、械斗排期 |
| 每次写入 | 脏标记 → 批量落盘（沿用 v1 的原子写 + `.bak`） |

> **catch-up 上限**：泡点 tick 补偿最多补 5 跳（10 秒）。
> v1 曾因机器卡顿一次补了几分钟的量，测试里出现"6 秒涨了 212 点"。

## 六、数据量估算

| 项 | 规模 | 说明 |
|---|---|---|
| 玩家 | ~20 | 每人存档约 8~15 KB |
| 交情 | ≤ 190 对 | 稀疏矩阵，几 KB |
| 挂单 | ~100 条 | |
| 见闻 | 每人约 400 个 id | 用位图或 id 数组均可 |
| 编年史 | 累积增长 | 只增不删，需分页 |

**总量在 MySQL 面前微不足道**，可以放心用简单实现，
不要提前优化。

## 七、待拍板

1. **见闻 `codex` 用 Set 还是位图？** id 数组最简单，
   400 个 id 约 3 KB／人，20 人 60 KB——直接用数组即可。
2. **五榜要不要实时算？** 20 人的量级可以每次请求现算，
   不需要缓存。但要防止 N² 的交情总和计算变慢。
3. **编年史只增不删，一年后会有多大？** 估计几千条，
   加个分页就够，不需要归档。
4. **`nonce` 去重表存多久？** 建议内存里保留 5 分钟，重启即清——
   重启后重发的概率可以忽略。
5. **离线泡点若要做**，`idle.last` 的语义要改（现在是"上次 tick"），
   需要区分"在线挂机"和"离线累积"。
