# UI 与信息架构 v0.2

> 第6项体验建议，2026-09-08，仅文档。承接[首版体验与验收](首版体验与验收.md)、[玩家流程](首版玩家流程.md)、[状态与反馈文案](界面状态与反馈文案.md)和[接口合同](命令与事件接口表.md)。本轮没有制作HTML原型、修改界面代码、运行浏览器或完成可用性/无障碍验收。
>
> 保留论坛式三栏、公共/个人信息分区、名字展示与移动端四入口。下面给旧稿未定部分一套明确推荐；布局、主题色和闭关聊天的选择仍待评审，不等于用户已经批准或现有v1界面已经实现它们。

## 1. 主界面要持续回答的五件事

1. 我在哪里、此刻正在修行/战斗/参观/古墓中的哪一种状态。
2. 气血、内力、等级和银两是多少；数据是否刚同步、连接是否中断。
3. 当前可以做什么、什么条件还没满足、下一步去哪里。
4. 此地有哪些真实玩家，我能否与他们说话。
5. 我的上次操作已经完成、被拒绝，还是尚未确认结果。

正文、按钮和数字都用玩家语言。`requestId/saveEpoch/controlRevision/commitId`等只进入用户主动展开的“问题详情”，复制时不含凭据或他人私有数据。日/周额度明确北京时间05:00，世界昼夜写游戏时辰，两者不混作“明天”。

## 2. 断点与页面骨架

| 可用宽度 | 布局推荐 | 保留的能力 |
|---|---|---|
| ≥1100 CSS px | 左状态/导航、中操作与消息、右此地人物/五榜 | 三栏均可见，中心是阅读与行动主区 |
| 768～1099 CSS px | 中＋右；左状态摘要留顶栏，地图进入可关闭抽屉 | 不删除人物名单；查看导航后回到原操作/输入草稿 |
| <768 CSS px | 单栏，场景/聊天/人物/我四个底部入口 | 登录默认聊天；顶端保留地点、连接、活动摘要与“此地N人”入口 |

断点以布局可用宽度判断，不按设备品牌。320 CSS px及放大字体时仍能纵向完成所有操作；横屏、软键盘或短窗口高度不足时，收起装饰与非当前详情，让操作区、消息与输入自然滚动，不强塞三个固定高度而把按钮挤出屏幕。

桌面建议左栏约212px、右栏约220px、中栏占余量；这是起始布局预算，不是禁止缩放的固定尺寸。顶部全局导航包含场景、任务、行囊、修习、名帖、见闻、市集、信箱、同道、玩法/设置；窄屏次级项并入“我”，不让顶栏横向溢出。家园/古墓从合法场景入口进入，“我”可显示已有家园或未完古墓的返回入口，但不会绕过等级/位置/权限。

### 中栏的四个位置

| 位置 | 内容 | 切换/尺寸规则 |
|---|---|---|
| 操作区 | 当前场景动作，或打开的任务/市集/配装/名帖详情 | 首屏只放当前目标、关键成本/结果和主动作；细节展开，长内容自身可滚动；可一键收起恢复消息阅读 |
| 公共消息 | 世界/本地/门派聊天、获准公开的公告 | 不被整个新面板替换；聊天筛选与阅读位置独立保存 |
| 个人消息 | 自己的任务结果、战斗行动、收支回执、重要通知 | 与公共分区；不是每2秒一行收入；不被他人的发言冲掉 |
| 输入区 | 当前频道/收件人、草稿、发送、未发送状态 | 打开面板不清草稿，不把“按回车”默认变成付费确认 |

桌面高度充足时两类消息同时可见；短高度时允许“公共/个人”分段切换，但活动摘要、另一分区的新消息文本计数和返回入口始终可达。关闭操作面板回到原聊天滚动位置；不打开新窗口，不让战斗变成独立全屏页面。

## 4. 聊天、个人回执与正在进行的动作

- 频道与收件人始终标明；切频道保留各自草稿，私聊不意外发到世界。中文输入法候选确认不发送；明确发送按钮始终可用，键盘快捷键有说明。
- 已持久提交后才显示“已发送”；本地草稿/发送中/待确认分别标记。同一消息补传不出现第二条；离线草稿不在重登后悄悄群发。
- 正在读历史时不强制滚到底；底部文本按钮“有N条新消息”带回最新，不把阅读锚点每2秒推走。公共与个人分别记阅读位置。
- XP、银两、气血等高频状态就地更新；个人收入按会话汇总可展开账目，完成任务、胜负、打造结果、成交、邀请等独立事件不可被合并丢掉。重连补发的旧事件显示历史时间，不重播新获得演出。
- 手机聊天顶端保留可展开的个人消息摘要，首屏最近10条并可继续查看；10条只是显示数量，不是删除其他持久结果。进行中战斗摘要与“继续操作”常驻，切聊天不暂停服务端机会。
- 私信与名帖新成就可用原两处未读徽标；其他状态采用当前位置的文本计数/摘要，不铺满顶栏红点，不每个日常库存都催领。
- 系统通知以可被辅助技术识别的状态信息呈现，不抢走正在输入的焦点；2秒泡点不逐跳朗读，关键拒绝/胜负/待确认才适度播报。[W3C 状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

**闭关聊天冲突的本轮推荐：**保留solo/risk/120分钟占位，取消旧场景稿“期间不能说话”的强制禁言。闭关可由玩家主动收起公共消息/静音，但仍可打开聊天、处理私信与关系拒绝；不因说一句话重置原修行。此项作为体验建议记录在总表，尚未替用户裁定；若另选强制禁言，必须连同F03聊天承诺、引导和受限提示一起评审，不能让程序悄悄忽略发送。

## 5. 页面内的关键交互

### 5.1 调查、案卷与学习

案卷首屏分为“已确认／他人说法／尚无定论”；只有服务端确认的证据入相应栏。对象检查列表可重读、顺序题有上移/下移按钮、配对/叠图有列表替代，不能只靠拖拽、颜色或在图上找几个像素。所有判断均给证据内的矛盾说明，不用“答错了”清整页。

目标达成、任务领奖、装备自选为不同状态；文字说明本次具体领取什么、此前已领什么。选择语气只改表达，不能显示不同奖励暗示道德路线。已完成主线回看只读；未知故事不提前显示“最终真相”。正式成礼确认展示派别、首技、入门武器与后续责任；试演借用技能始终标“本次试演”，不能混进永久已学栏。

### 5.2 战斗与技能

普通攻击、合法主动技、已允许的物品与退出选择用按钮清楚区分。不可用技能显示原因（未学、内力不足、冷却、武器不兼容、当前控制），读详情不提交行动。手动剩余时间来自服务端期限；点击后显示提交/已接受结果，不在UI计时结束或动画回调再结算伤害。

多段、护盾、保护复生、反击及延迟事件按已提交日志顺序展示；允许合并低级视觉细节，完整文本记录可回看。手动超时的普通攻击/跳过是既有合同结果，倒计时不能让客户端另发第二动作。世界PvE/切磋断线会继续托管，古墓冻结不同；在相应界面提前说明，不统一写“掉线自动暂停”。

### 5.3 装备、工坊与市场

六槽与普通行囊48件分别计数，材料/种食/票用自身上限。装备卡至少有部位、正式名称、品质文字、+级、所需等级、绑定与可用状态；选择比较时明确比较当前槽和当前有效条件。`+12 ↑ / −5 ↓`配文字解释，不用红绿作为唯一信息。

报价首屏列实际支出、材料绑定来源、手续费、预期产物范围、不可恢复的改变和容量后果。打造结果未知时只显示概率/可能结果；不能预抽本次词条给用户看。一次报价面板即完成必要确认，不把每次普通购买再叠两次相同弹窗；分解/丢弃/归还等不可逆操作保留明确确认。

投入传承页面同时列原装备变为+0、目标仍+0、实际投入抵扣额度与手续费，不写“复制强化”。市场展示整单总价与数量，参考价不叫保底回收价；材料流通属F16，普通装备是否开放按D04，绑定/十声不能因找到按钮就成交。已挣奖励/归还物满仓进入待领时展示同一物品与来源；不把它显示成另一次抽奖机会。

### 5.4 日常、家园与古墓

日常将“资格还剩多少”“目标是否完成”“奖励是否已领”分开。批量处理提供待领明细与逐份状态，部分成功不把整批写失败后重发。值守方式说明所需有效在线分钟，可继续聊天；不能把等30/90分钟写成只需点击一分钟却省略等待。

家园每格显示空地/生长/成熟/枯萎、可核对的绝对时刻及倒计时。库房与公共材料是一份账；炉忙/未领、食物预约容量、日帽分别解释。参观者无种植/收取/库房明细动作，撤权免费返回，不用空白报错页处理。

古墓地图必须同时有文本路径列表：当前层、当前列、合法下一节点和已知类型。哑巴铃隐藏类型时只隐藏合同允许的类型，不隐藏“这是合法出边”或按钮名称；不得通过替代文字/tooltip泄漏隐藏类型。入场前展示次/票与失败保留规则，扣款成功后才出现5选2；局内冥钱/临时药与永久银两/食物分区。撤出确认基于当前已提交阶段给带出明细及周帽，不显示尚未抽到的奖。第三层主胜利直接展示同一结算结果，无第二次“再领通关奖”。

## 6. 字体、数字与颜色

正文推荐系统中文无衬线16px、行高1.6；标题按层级，次文本不低于14px作为默认，用户放大不强制缩回。长段建议一行约35～50个汉字，窄屏自然换行。原“首屏20行”改为信息优先级预算，不截断必要费用、条款、故事证据或按钮来凑行数。

攻击/防御等展示实际值及可展开来源；没有可复核同级样本就不标“同级偏上/前百分之几”。HP/MP/XP按数值合同显示两位，正值极小时显示“<0.01”，不把显示0误判死亡。银两显示可支付分、连续尾数可在明细说明；封顶写“60级·已至上限”，不显示虚假的下一等级。倒计时可平滑显示但不触发本地发奖。

### 6.1 主题与基础色

建议默认跟随系统，可手动选浅/深/跟随系统，选择可保存在本设备。主阅读面固定浅`#FAFAF7`、深`#171B21`；正文浅`#333333`/深`#DDDDDD`，次文本浅`#626974`/深`#B0B8C2`。状态、姓名、品质文字始终放在明确背景上；hover/选中/错误背景另测，不沿用只对主背景的结论。

## 7. 键盘、手机与低负担阅读

- 所有核心操作可用键盘完成；焦点顺序跟阅读顺序，打开必要确认面板聚焦标题/首个相关控件，关闭回触发按钮。普通消息到达不移动焦点。Esc只关闭面板/取消未提交草稿，不暗中撤出古墓或销毁正在提交的订单。
- 软键盘打开时输入与发送按钮可见，未提交内容不被底部导航遮挡；当前聚焦控件不能被固定顶部/底部完全覆盖。项目进一步推荐完整露出当前操作控件。[W3C 焦点不被遮挡说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- 本项目建议常用触控目标至少44×44 CSS px；这比WCAG 2.2 AA的24×24最低目标尺寸更宽裕，后者包含间距、行内等例外，不能把44误称标准强制值。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 验证320 CSS px重排、200%文字放大及1280视口400%浏览器缩放；流程信息和按钮不丢、不靠整页横向滚动。古墓分支、装备比较、任务叠图均给线性文本替代，不默认以“图表”为由豁免整页。[W3C 重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- 自动播报可暂停，辅助技术可读到按钮名称、选中态、展开态、错误关联与剩余关键条件；关键内容不只出现在hover。明确状态变化见状态文案表。
- 默认静音；遵循用户减少动态效果的偏好，提供“文字/精简/标准”呈现。没有图片、声音或动态效果仍能调查、战斗、配装、交易与领奖。装备已有有限CSS/SVG表现可在标准模式制作，不强制改为3D/视频，也不删原唯一武器的文字身份表达。
- 手动10秒输入是战斗规则，界面倒计时应清楚且自动策略始终可选；可用性测试若发现任务强迫手动速度才能完成，记为设计阻塞，不能以“网络慢”概括所有问题。

## 8. 五线展示与名单

右栏五榜默认每榜最多5人，完整列表在名帖/榜单页；不足5人显示实际人数，不造机器人占位。自己未上榜也可看自己有依据的进度；名次并列、计分公式以原领域事实/已发布规则为准，UI不新造综合五线总分。名帖有战力/名望/见闻/家业/人情五区，社会记录按公开同意与访问权限过滤，不能因为有accountId就展示私账。

手机“此地N人”条可进入人物页，保留原聊天草稿；无其他真人时写“此地只有你，可去其他公共场景看看”，普通NPC单独标识。第二行展示关系档、派别及已获授权的当前状态，不能精确广播别人的任务答案、私宅库存或古墓隐藏节点。

隐藏/未开放内容不算收藏缺失：幽潮、未选D01鱼药等不拉低完成度；86成就仅是候选。首发五线仍须各有真实可达积累和展示，不能用一张“敬请期待”名帖冒充F19完成。
