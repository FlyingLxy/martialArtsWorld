# 设计原则

后面所有设计都得先过这几条。不是教条，但要推翻得给出理由。

> **设计基线**：这套设计**不继承现有游戏的等级、地图、任务**，落地时清档重来。
> 唯一沿用的是**泡点框架**（每 2 秒结算、场地门槛、超出衰减、挂着就涨关掉就停）。
>
> 文档里凡是提到 v1 "实测"的数字，都不是约束，而是**已经踩过的坑的证据**——
> 留着是为了别再踩第二遍。
>
> **注意分寸**：可以引用 v1 的数据说明"这种形状会出问题"，
> 但**不要把 v2 的数值设计成"在 v1 基础上调整"**。v2 的每个系统都从零定义，
> v1 只提供反面教材，不提供起点。

### 引用 v1 的数字，一律加标记

这条是踩了三次才立的规矩。犯错的样子都一样——
不是有意继承，是**文档里 v1 和 v2 的数字长得一模一样**，
写着写着就顺手拿来当默认值了：

- 打造曲线拿 v1 的 5263／195652／×2.08 当基础推 v2
- 打造上限默认成 v1 的 +9，而 v2 的上限根本还没定
- 装备耐久按 v1 的玄铁重剑 8000 两算出"维护费占收益两成"

**所以：凡是引用 v1 的数，写成固定格式 `v1 实测：xxx`。**

好处有三个：写的时候会多想一秒这数能不能用；看的人一眼知道它不是约束；
以后 `grep 'v1 实测'` 就能把全部引用点扫出来复查。

**同一个坑还有个变种：数词频当证据。** 我数了"命中"在天赋文档出现 81 次，
就断定它是主力属性，并据此设计了装备词条和溢出规则——
逐条读才发现只有 5 处真在改命中率，其余全是「命中后触发」这类事件条件。
**看一个词出现多少次，不等于看懂它在做什么。**

还有两条判断标准：

- **只能用来说"这种形状会出问题"，不能用来推出 v2 的任何一个数。**
  区别在于：前者是证据，后者是起点。
- **凡是 v2 还没定的东西，宁可写 `【待填】`，也别填一个 v1 的数占位。**
  占位符会活下来变成定案——这三次全是这么发生的。

## 一、这游戏的核心是「待着」，不是「玩着」

玩家 90% 的时间是挂着页面在干别的。所有设计都要先问一句：
**这东西会不会逼人一直盯着屏幕？**

- 加内容 ✓　　加负担 ✗
- 上线有事可做 ✓　　不上线就亏 ✗
- 主动玩更快 ✓　　不主动就掉队 ✗

**推论**：任何"每天必须做否则亏"的设计都要打个问号。日常可以做，但要能攒、
不做没惩罚、且有一部分挂着就能完成（见[任务系统](任务系统.md)）。

## 二、地图不是用来走的，是用来待的

所以地图设计的核心问题只有一个：**凭什么待在这儿而不是那儿？**

现在的答案只有「等级门槛 + 超出就衰减」，一个维度导致每个等级段都有唯一最优解，
玩家算一次就再也不用想了。要让这个决策变有趣，得有互相冲突的维度
（见[地图系统](地图系统.md)）。

## 三、社交是目的，不是手段

当年江湖聊天室好玩的从来不是泡点本身，是**一屋子人一边泡点一边胡侃**。
所以：

- 把人聚在一起的设计优先（`crowd` 加成、请客、集市、活动）
- 逼人单机的设计要克制（`solo` 场景可以有，但别成为主流路线）
- 花钱的动作最好同时是社交动作（请客、送花、成亲摆宴都是这个思路）

## 四、任何产出都要有上限，任何货币都要有出路

这是最容易翻车的一条，已经踩过一次：怪物经验不随等级衰减，
导致**刷怪比泡点快 858 倍**，"泡点江湖"里泡点成了最没用的成长方式。

**加任何新东西之前，先回答三问**（详见[经济与成本](经济与成本.md)）：

1. **它的产出是泡点的几倍？** 超过 5 倍要警惕，超过 20 倍一定出事。
2. **它有没有上限？** 无上限的产出必须配上限机制——冷却、每日次数、等级压制。
3. **对应的回收在哪？** 新增产出必须同时想好这些钱去哪儿，**不能只管发不管收**。

### 四之一：主动行为必须有成本

现在打一场怪的净成本约等于零——打坐免费无限回血、金疮药自己会掉、
内力几秒回满。**成本为零的行为一定会被刷爆**，任何"多打多得"的设计在它面前都失效。

成本可以是钱（药、修理费），但**时间成本更适合挂机游戏**：
挂机的人不缺时间，主动刷怪的人才受它约束。

### 四之二：惩罚要疼，但不能拿走"玩"本身

现在死一次只丢一成银两，打坐三下满血继续，**风险设计全部失效**。惩罚要加，但两条边界：

- **不做"一段时间内不能玩"**（禁止战斗、强制等待、**赶路读条**、体力耗尽下线）。
  这类设计拿走的是游玩时间，玩家记恨的不是损失，而是干坐着。
  换成**状态惩罚**（变弱但能继续）或**花钱**（车马费、请郎中）——
  痛感在，选择权也在，还顺带成了回收口。

  分界线：**让行为变慢**（战斗要十几秒、打坐有冷却）可以，
  **让人干等**（读条、倒计时、冷却期什么都做不了）不行。
- **不连坐挂机的人。** 惩罚落在"主动玩"上，挂机的本来就没在打架。

同理，**惩罚鲁莽而不惩罚尝试**：偶尔失手是学习成本，短时间内连续送死才该加重。

### 四之三：升级需求必须追得上输出增长

`need(lv)` 是 `lv^1.75`，而玩家输出是 **属性 × 武功倍率 × 打造倍率**（三者相乘）。
结果是**等级越高升级越轻松**（10 级要打 25 只怪，80 级只要 4.7 只），
这是数值膨胀的根子。要么把曲线改陡，要么靠等级压制顶住。

## 五、保住零构建

clone 下来 `node server.js` 就能跑，没有 webpack、没有 npm run build。
这个性质对协作者友好，值得为它牺牲一些便利（比如前端不用框架）。

## 六、诚实

- 不做"看起来随机其实保底"的欺骗式概率
- 机器人可以有，但不能让玩家**误以为在跟真人交易或结拜**（见[江湖散人](江湖散人.md)）
- 不做逼氪设计——这游戏不收费，也别做出收费游戏的坏习惯

## 七、先想清楚回收，再想产出

新功能的设计顺序应该是**反的**：先问"这会产出多少、怎么收回来"，
再设计玩法。反过来做，等你发现通胀的时候，已经有人攒了两百万两，
削回去就是伤害玩家，不削就是放任崩坏——两边都难看。

[经济与成本](经济与成本.md)里有现有产出与回收的完整盘点，加东西前先看一眼那张表。

## 八、任何事情都不该一成不变

**凡是会重复很多次的行为，都要有概率。** 而且不只是"成功／失败"两档，
要**有惊喜也有事故**——玩家记得住的从来不是"我打了一百只怪"，
而是"我那次三个点的大成功"。概率是故事的来源，也是留存的来源。

需要有概率的地方（不完全）：

| 环节 | 好的一面 | 坏的一面 |
|---|---|---|
| 战斗 | 暴击、连击、技能触发、闪避 | 被暴击、技能落空、被定身 |
| **怪物** | —— | **怪也要会放技能**，不能只有普攻挨打 |
| 打造 | 大成功（一次 +2） | 失败、大失败（掉两级） |
| 掉落 | 稀有、极品（额外属性） | 空手而归 |
| 泡点 | 奇遇（捡钱、顿悟、遇高人） | 走火入魔 |
| 采集／钓鱼 | 极品鱼、稀有种子 | 跑空 |

**推论：任何"几回合""几分钟""几两"的设计指标，都必须配一个区间。**
只写期望值等于默认它是定值，实现的人就会照定值去调，概率就名存实亡了。
区间怎么给：写"八成落在 A~B"，比写"±X%"更直观，也更容易验收。

**但要防两件事**：

- **别太黑。** 连续失败会劝退。可以做**隐性怜悯**（连败几次后悄悄提高成功率），
  但别做成明面上的保底——保底一出，随机就没意义了，玩家会开始"算"。
- **别假随机。** 不做"看起来是概率其实是脚本"的设计，也不做暗改概率。
  见本文第六条。

## 九、后期投入必须换来更大的收益

**边际效应递减会杀死所有长线系统。** 如果每一级提升都一样多，
而成本和风险却一路飙升，理性玩家会在某个点停下——后面的内容等于没做。

反过来做：**越往后，每一级涨得越多**。用阶梯，并让每个台阶的起点成为
效率甜点——跨进新档的第一级，单位收益的成本要比上一档最后一级更低，
这样玩家在边界上是被拉进去，而不是被劝退。方法见[数值基准](数值基准.md)。

适用于任何"可以一直投入"的系统：装备打造、天赋深度、声望档位、家园等级。

## 十、明线公开，真相散落

游戏内所有剧情内容采用**魂游式的碎片化叙事**：世界的完整面貌不由一个 NPC、
一条任务或一本设定集直接讲完，而是散落在装备介绍、NPC 对话、场景描述、
招式与技能文案、怪物行为、任务物品和环境变化中。

但碎片化不等于什么都不说。每一部主线都必须提供一条人人可见、可理解、可完成的**公开明线**，
至少说清四件事：

1. 玩家正在处理什么事。
2. 眼前的主要冲突在谁之间。
3. 失败或放任不管会造成什么后果。
4. 本章结束时真正解决了什么。

主线不负责公布世界的全部答案。玩家如果只跑主线，也能理解当前故事；
如果愿意读细枝末节，则能发现事件的前因、人物的偏见、被删改的历史，
以及主线结论里仍然无法解释的矛盾。

### 十之一：三层信息

| 层级 | 玩家能知道什么 | 主要载体 | 写法 |
|---|---|---|---|
| **公开事实** | 当前目标、冲突、已发生事件和章节结果 | 主线任务、必经 NPC、章节结算 | 可以直说，不故弄玄虚 |
| **可证真相** | 人物动机、历史关系、隐藏因果 | 装备、场景、支线对话、招式描述 | 至少由两条不同来源的碎片相互印证 |
| **未定猜想** | 世界本质、神谕、远古历史和未来危机 | 单方记载、矛盾口供、异象 | 可以互相冲突，不急着给官方正解 |

### 十之二：碎片不能变成解谜门槛

- 任务目标、地图入口、关键操作和当前敌人不藏在冷门装备文案里。
- 一个会改变主要结论的真相，不得只有一条可错过、可销毁或低概率掉落的证据。
- 隐藏剧情的奖励主要是新对话、案卷、称号和支线，不是必需战力。
- 玩家看过的装备、场景、招式和重要对话应进入可回顾的“见闻录”，不要逼人为了剧情永久占着背包。

### 十之三：开发侧不能也碎掉

魂游式的是**玩家如何接触信息**，不是团队如何管理设定。
每一章仍要在开发文档内集中维护一份“真相表”：

```text
已确认事实   世界中实际发生了什么
公开明线       主线会直接告诉玩家什么
碎片证据       哪些装备/NPC/场景/招式在暗示它
未定部分       哪些只是角色的理解，尚无官方答案
```

否则设定会在不同文案中自相矛盾，且团队无法分辨那是有意留白还是写错了。

## 十一、不要只有一把尺子

如果所有玩法最后都折算成同一个数（战力），那玩法再多也只有一种动机，
**排在后面的人做什么都没意思，因为唯一的尺子上他就是矮**。

一个玩法能不能加，除了看产出和回收，还要看**它喂给哪条追求线**：
战力、名望、见闻、家业、人情——至少喂一条，且不能只喂战力。
只喂战力的玩法，本质上是打怪的换皮。

**五条线之间不可互相折算。** 一旦能换，玩家就会算出哪条最划算，
五条又坍缩回一条。

**每条线都必须有展示位。** 在十来个人的服务器上，"被别人看见"就是回报；
没有展示位的追求线等于不存在。详见[玩法与核心循环](玩法与核心循环.md)第二之一节。
