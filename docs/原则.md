# 设计原则

后面所有设计都得先过这几条。不是教条，但要推翻得给出理由。

> **设计基线**：这套设计**不继承现有游戏的等级、地图、任务**，落地时清档重来。
> 唯一沿用的是**泡点框架**（每 2 秒结算、场地门槛、超出衰减、挂着就涨关掉就停）。
>
> 文档里凡是提到"旧版""实测"的数字，都不是约束，而是**已经踩过的坑的证据**——
> 留着是为了别再踩第二遍。

## 一、这游戏的核心是「待着」，不是「玩着」

玩家 90% 的时间是挂着页面在干别的。所有设计都要先问一句：
**这东西会不会逼人一直盯着屏幕？**

- 加内容 ✓　　加负担 ✗
- 上线有事可做 ✓　　不上线就亏 ✗
- 主动玩更快 ✓　　不主动就掉队 ✗

**推论**：任何"每天必须做否则亏"的设计都要打个问号。日常可以做，但要能攒、
不做没惩罚、且有一部分挂着就能完成（见[任务系统](任务系统.md)）。

## 二、地图不是用来走的，是用来待的

所以地图设计的核心问题只有一个：**凭什么待在这儿而不是那儿？**

现在的答案只有「等级门槛 + 超出就衰减」，一个维度导致每个等级段都有唯一最优解，
玩家算一次就再也不用想了。要让这个决策变有趣，得有互相冲突的维度
（见[地图系统](地图系统.md)）。

## 三、社交是目的，不是手段

当年江湖聊天室好玩的从来不是泡点本身，是**一屋子人一边泡点一边胡侃**。
所以：

- 把人聚在一起的设计优先（`crowd` 加成、请客、集市、活动）
- 逼人单机的设计要克制（`solo` 场景可以有，但别成为主流路线）
- 花钱的动作最好同时是社交动作（请客、送花、成亲摆宴都是这个思路）

## 四、任何产出都要有上限，任何货币都要有出路

这是最容易翻车的一条，已经踩过一次：怪物经验不随等级衰减，
导致**刷怪比泡点快 858 倍**，"泡点江湖"里泡点成了最没用的成长方式。

**加任何新东西之前，先回答三问**（详见[经济与成本](经济与成本.md)）：

1. **它的产出是泡点的几倍？** 超过 5 倍要警惕，超过 20 倍一定出事。
2. **它有没有上限？** 无上限的产出必须配上限机制——冷却、每日次数、等级压制。
3. **对应的回收在哪？** 新增产出必须同时想好这些钱去哪儿，**不能只管发不管收**。

### 四之一：主动行为必须有成本

现在打一场怪的净成本约等于零——打坐免费无限回血、金疮药自己会掉、
内力几秒回满。**成本为零的行为一定会被刷爆**，任何"多打多得"的设计在它面前都失效。

成本可以是钱（药、修理费），但**时间成本更适合挂机游戏**：
挂机的人不缺时间，主动刷怪的人才受它约束。

### 四之二：惩罚要疼，但不能拿走"玩"本身

现在死一次只丢一成银两，打坐三下满血继续，**风险设计全部失效**。惩罚要加，但两条边界：

- **不做"一段时间内不能玩"**（禁止战斗、强制等待、**赶路读条**、体力耗尽下线）。
  这类设计拿走的是游玩时间，玩家记恨的不是损失，而是干坐着。
  换成**状态惩罚**（变弱但能继续）或**花钱**（车马费、请郎中）——
  痛感在，选择权也在，还顺带成了回收口。

  分界线：**让行为变慢**（战斗要十几秒、打坐有冷却）可以，
  **让人干等**（读条、倒计时、冷却期什么都做不了）不行。
- **不连坐挂机的人。** 惩罚落在"主动玩"上，挂机的本来就没在打架。

同理，**惩罚鲁莽而不惩罚尝试**：偶尔失手是学习成本，短时间内连续送死才该加重。

### 四之三：升级需求必须追得上输出增长

`need(lv)` 是 `lv^1.75`，而玩家输出是 **属性 × 武功倍率 × 打造倍率**（三者相乘）。
结果是**等级越高升级越轻松**（10 级要打 25 只怪，80 级只要 4.7 只），
这是数值膨胀的根子。要么把曲线改陡，要么靠等级压制顶住。

## 五、保住零构建

clone 下来 `node server.js` 就能跑，没有 webpack、没有 npm run build。
这个性质对协作者友好，值得为它牺牲一些便利（比如前端不用框架）。

## 六、诚实

- 不做"看起来随机其实保底"的欺骗式概率
- 机器人可以有，但不能让玩家**误以为在跟真人交易或结拜**（见[江湖散人](江湖散人.md)）
- 不做逼氪设计——这游戏不收费，也别做出收费游戏的坏习惯

## 七、先想清楚回收，再想产出

新功能的设计顺序应该是**反的**：先问"这会产出多少、怎么收回来"，
再设计玩法。反过来做，等你发现通胀的时候，已经有人攒了两百万两，
削回去就是伤害玩家，不削就是放任崩坏——两边都难看。

[经济与成本](经济与成本.md)里有现有产出与回收的完整盘点，加东西前先看一眼那张表。

## 八、任何事情都不该一成不变

**凡是会重复很多次的行为，都要有概率。** 而且不只是"成功／失败"两档，
要**有惊喜也有事故**——玩家记得住的从来不是"我打了一百只怪"，
而是"我那次三个点的大成功"。概率是故事的来源，也是留存的来源。

需要有概率的地方（不完全）：

| 环节 | 好的一面 | 坏的一面 |
|---|---|---|
| 战斗 | 暴击、连击、技能触发、闪避 | 被暴击、技能落空、被定身 |
| **怪物** | —— | **怪也要会放技能**，不能只有普攻挨打 |
| 打造 | 大成功（一次 +2） | 失败、大失败（掉两级） |
| 掉落 | 稀有、极品（额外属性） | 空手而归 |
| 泡点 | 奇遇（捡钱、顿悟、遇高人） | 走火入魔 |
| 采集／钓鱼 | 极品鱼、稀有种子 | 跑空 |

**但要防两件事**：

- **别太黑。** 连续失败会劝退。可以做**隐性怜悯**（连败几次后悄悄提高成功率），
  但别做成明面上的保底——保底一出，随机就没意义了，玩家会开始"算"。
- **别假随机。** 不做"看起来是概率其实是脚本"的设计，也不做暗改概率。
  见本文第六条。

## 九、后期投入必须换来更大的收益

**边际效应递减会杀死所有长线系统。** 如果每一级提升都一样多，
而成本和风险却一路飙升，理性玩家会在某个点停下——后面的内容等于没做。

反过来做：**越往后，每一级涨得越多**。用阶梯，让每个台阶的起点都是甜点，
玩家有动力冲过去。具体见[数值基准](数值基准.md)的打造曲线。

这条不只适用于打造，任何"可以一直投入"的系统都适用（天赋深度、
声望档位、家园等级）。
