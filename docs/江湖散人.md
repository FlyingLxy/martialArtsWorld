# 江湖散人（机器人）

## 为什么要

这游戏的灵魂是「一屋子人一边泡点一边胡侃」。**人少的时候，灵魂就没了**——
新人第一次进来，左下角每个房间都是 0，公共频道一片死寂，
他不会觉得"这游戏冷清"，他会觉得"这游戏是坏的"。

机器人的作用不是替代玩家，是**保证任何时候进来都有人气**，撑到真人来。

文字游戏在这件事上有天然优势：不用做 3D 动作、不用寻路，
一个机器人只要会走动、会泡点、偶尔说句话，就足够像。

## 行为设计

| 行为 | 怎么做 | 备注 |
|---|---|---|
| **待着** | 在某个场景泡点，状态显示"修行中" | 最基本的，让房间人数不为 0 |
| **走动** | 每几分钟换个地方，符合自己的等级段 | 别乱窜，30 级的不该跑去新手村 |
| **说话** | 情境触发 + 预设台词库 | 见下 |
| **回应** | 有人对它做虚拟动作／打招呼时，有一定概率回应 | 简单关键词匹配即可 |
| **切磋** | 可以被挑战，用现成的「影子」机制 | 不需要真的实时战斗 |
| **升级** | 缓慢涨等级，风云榜上有名有姓 | 别涨太快，也别停滞 |

### 说话的设计

**别做成刷屏机器人**。台词要稀疏、要贴合情境：

- 进出房间时偶尔招呼一句
- 有人升级／打赢擂台时接一句
- 深夜里说点应景的
- 隔很久才在世界频道冒一句

宁可少说，也不要让人一眼看出是循环播放的。**一小时说三五句就够了。**

### 数量控制

**机器人是补位的，不是主角。** 数量应该随真人在线数**反向**调整：

```
真人 0 人  →  散人 4~5 个
真人 3 人  →  散人 2~3 个
真人 8 人+ →  散人 0~1 个
```

真人多起来的时候，机器人该悄悄退场。

## 必须守住的边界

这是设计里最要紧的部分，因为它涉及**会不会骗到玩家**。

| 能做 | 不能做 |
|---|---|
| 在房间里待着、泡点、走动 | **收玩家的钱**（塞钱、买摊位、押注） |
| 说话、回应虚拟动作 | **卖东西给玩家**（假装交易对手） |
| 被挑战切磋 | **成亲、结拜**这类有真实情感投入的关系 |
| 上风云榜 | **主动声称自己是真人** |

**核心原则**：机器人可以让世界显得热闹，但**不能让玩家在有真实代价的事情上误判对象**。
一个人为了跟"某某"结拜而攒了三天银子，结果发现对方是程序——这是伤害，不是趣味。

## 要不要明示

两种做法，各有道理：

**A. 给个不显眼的标识**（比如称号固定为「江湖散人」，或者名字有统一风格）
- 诚实，玩家发现时不会有被骗感
- 老玩家反而会觉得有意思（"这几个是系统的"）
- 代价：热闹感打折

**B. 完全不标识**
- 代入感最强
- 但一旦被识破，玩家会回想"我之前跟它说的话都是对着空气"，体验是负的
- 而且违反[设计原则](原则.md)第六条

**倾向 A**，但配合"边界"那节的限制，B 也不是不能接受。**这条需要拍板。**

## 技术方案（草案）

- 不走真实 SSE 连接，在服务端维护一批虚拟玩家对象
- 参与 `online()` / `inRoom()` 的返回，这样房间人数、风云榜自然包含它们
- 一个独立的调度器驱动行为（`server/bots.js`，新模块）
- **不参与存档**（RUNTIME 字段），重启后重新生成
- **不产出任何经济物品**——它们杀怪不掉落、不积累银两进入流通

最后一条很重要：机器人如果能产出，就成了通货膨胀的源头。

## 待拍板

1. **明示还是不明示**（见上）
2. **机器人能不能被玩家杀？** 能的话，杀了给不给经验？（给了就是刷经验漏洞）
3. **要不要让机器人参与秘境／攻防战凑人数？** 好处是活动开得起来，
   坏处是"跟机器人打赢了攻城战"很空虚
