## 进入各阶段前

当前六项准备覆盖范围、数值、内容、经济、数据接口和体验验收。某阶段开工前，其直接依赖的文档必须足够明确：

- 范围已登记；若涉及范围表 D 项，先完成相关决定，不能由实现者自行删减。
- 使用同一数值基准和真实内容引用；数据表有稳定 ID、条件、奖励和来源。
- 钱货、进度、时间和恢复有接口合同；关键成功/失败路径有验收用例。

允许先完成早期阶段所需的文档，再补中后期内容；不能把早期已经依赖的规则留到最后。准备第 2 项已给出[数值基准](数值基准.md)与[属性合同](属性成长与叠加规则.md) v0.2 文档；新参数仍需动态验证，本排期不复制另一份数值或把历史模拟场数作为当前验收真值。

第3项[首版内容数据总表](首版内容数据总表.md)已登记实际ID、模板、任务和逐阶段数量；各期直接使用该表引用。第4项[日常与经济方案](日常与经济方案.md)已补具体经济提案；登记稿仍有D03/D04裁定、实际平衡、接口与体验关口，不能把“表已写”当作进入全面开发或发布验收通过。

第5项已形成[数据合同](数据模型与接口.md)及五分表：M0按单写者持久提交、稳定ID、双revision、精度与时钟实现；涉及交易/家园/古墓/唯一武器的阶段必须接同一原子边界。第6项[首版体验与验收](首版体验与验收.md)及五份配套文档已补16流程、16界面、状态反馈和80组用例，每期按其证据格式逐项执行。当前只有合同、文案及静态检查，没有写处理器或跑恢复/试玩测试，阶段均未通过。

## M0 · 统一地基

对应 F01/F02/F24，以及 F03/F13/F16/F23 的最小技术切片。具体启用集合与实施决定统一读[M0实施基线](M0实施基线.md)；本阶段是封闭技术世界，不是缩小后的 M1，也不继承为正式玩家成长。高级玩法关闭不等于对应 F 项取消。

| 交付 | 验收 |
|---|---|
| 1～60 级公式、四维、精度与六件真实初装 | 数值使用同一已收口基准；初装按实际模板生成一次并保存，HP/MP/XP与尾数沿数学合同。ISO验证升级/封顶不等于已经自然走通1～60 |
| 稳定身份、四个真实出生安全点与最小manifest | XH/HY/HG/LM分别落到悦来客栈、老渡口、官驿、龙门石桥；六件初始化、账号角色链接、资格、receipt与outbox同一提交。未启用相邻地点保留阶段说明，不可执行移动 |
| 资源命令、幂等与存档基础 | 用同一初装uid“卸下→重新装备”完成连续两次提交，重试、拒绝、回执丢失和重启后不复制或丢失物品；不为技术链新增商店、赠金或调试领奖入口 |
| 在线积分与公共周期原语 | 四出生点使用真实g=1、基础C=0.8；独处XH的24有效秒手算增XP=16/3、银两1两。多连接不双算，无lease/停服不补；C=1只作独立ISO算例 |
| 公共原矿的整数产物 | `source.home.raw_ore`仅开启公共子来源，给`mat.raw_ore`；`binding.kind=unbound`，分量保留sourceId/commit来源。每3600有效秒1、日6、持有50，满仓仍记已处理额度，05:00清未满小时且不补离线。AC-43仅公共产出子项，家园/加工/购买/市场关闭 |
| 九类资格总账 | 按原等级与日周规则实现初始化、补期、水位和容量；创角仅DQ5/精力100/蓝资格12。20/40/50级等高阶资格通过ISO检查，但不开放其任务、战斗、古墓或奖励消费 |
| 最小技术界面与恢复 | 登录/四故乡选择、当前场景/修行开关、人物/六槽、个人回执与连接恢复可操作。服务仅绑定本机127.0.0.1；M0验桌面及375视口/触控模拟ISO，真机触控/软键盘UX留M1，模拟不记真机通过。完整聊天、任务和16界面仍随M1～M4交付 |
| 检查与故障基础 | 单写者、journal、快照与CURRENT、随机结果/业务去重、未知引用隔离和恢复有实际检查；只关闭[验收用例表](首版验收用例表.md)§2.1列出的M0子项 |

**首条运行链：**准备态根校验 → 激活真实最小manifest → 注册/创建杏花村角色 → 有效连接下修行24秒 → 停修 → 卸下麻边巾并重新装备同uid → 退出/重启 → 重登查询原回执及资产。另三个故乡复验出生、初始化与恢复；这不要求先完成24条序章或44个故乡/传承组合。

公共原矿在M0作为同一在线积分器的真实整数产物；来源名含home不要求先安家。任务消费、世界战斗和加工购买仍在M1/M2按原里程碑接入，不把周期/积分原语通过写成这些消费者已通过。家园离线生产、古墓24小时run、唯一武器90天回收及跨玩家市场在所属阶段接同一底座，不能要求M0先做完这些玩法。

**出口：**上述技术链及M0子项均有真实执行证据，已确认的身份、六件物品、资格、XP/银两、原矿和回执可恢复。M1仍完整保留四故乡16景、四条赴洛路线与24序章；高级用例和自然成长记录仍为未执行，不沿用旧版本测试数量补齐。

**内测入口约束：**15 级安家与 20 级浅探如果尚未实现，测试服明确显示暂未开放；仅依赖它们的引导、任务、图纸和配方暂不投放。当期装备材料必须有已定且可实际获得的替代渠道；如没有，就把必要的安家/古墓切片前移到 M2，不用调试发料代替成长。M3 完成后须从新号重验原等级入口。

## M5 · 发布验收

M5 主要做联验、修正和发布准备，不在此时首次加入完整新玩法。

1. **战斗与成长：**按已收口基准复验无装备、精品标准装、终局装备，覆盖成长等级、未学齐技能、天赋/套装/技能增级联动；M2/M4 的验证按最终版本复核。
2. **经济与时间：**检查主动/泡点比例、材料供需与回收、攒存和日周边界；实测每日常规任务负担不超过 15 分钟。旧12+8=20分钟是历史预算；第4项改共用5次并列主动/修行替代，≤15分钟仍是待实测目标，不是已通过结果。
3. **数据与恢复：**命令重试、离线成交、多窗口、断连、重启、禁地续局和唯一资产故障演练通过。
4. **体验与展示：**桌面和手机能完成已发布核心流程；五线均可见，隐藏/锁定/未开放状态不误导。
5. **运营准备：**配置、备份、恢复与清档演练完成；确定记录保留、问题观察与恢复步骤。

**出口：**实际执行的测试和人工验收记录齐备，无未关闭的首发阻塞项。模拟预算通过不能替代实际战斗、经济或恢复验证。

## 清档与记录保留

v1→v2 保留账号与登录凭据，清空旧角色等级、装备、银两、任务、场景进度；v1 首个记录不带入 v2。v2 正式世界产生的 world.firsts、编年史与专题规定的永久记录按合同保留，不因普通清档随意抹去。

阶段内测使用的测试记录是否转入正式世界必须在内测前写清。清档脚本、存储实现和演练属于后续开发，本轮只约定文档责任。
