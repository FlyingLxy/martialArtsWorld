### 2.1 账号版本与创角链接是两次实际变化

下面仅列版本字段，完整账号仍需凭据引用及角色链接等字段。注册创建账号时 `account.revision=1`；随后的创角事务更新真实角色链接，因此变为2。`authRevision`是独立的凭据/会话失效版本，本例初始1，创角不增加；不能用它代替账号命令的expectedRevision。已成功注册/创角的重试只查原回执，两个版本均不再增加。

```json
{
  "documentFixture": true,
  "recordType": "accountVersionExample",
  "accountId": "account.fixture.new",
  "afterRegistration": {
    "revision": 1,
    "authRevision": 1
  },
  "afterCharacterCreation": {
    "revision": 2,
    "authRevision": 1
  }
}
```

初始角色XP为固定18位0和有符号尾差0/1；`idle.intentEnabled=true`来自创角采用值，但没有合法连接lease仍收益0。用户后来主动停修保存false，登录和重启恢复都保留它。真实创角的HP/MP锚点须由六件实际初装计算满值生成；第4.2节的3与2是专门的数学夹具，不是给真实新号发3点最大HP。

## 3. 一条跨角色资源命令：买10原矿

这是F16普通材料市场的文档案例，示例税费按第4项推荐；**M0不启用市场命令，此段不是M0已可执行接口样本**。D04未裁不取消已保留的材料流通，但普通装备交易须另验D04开关。`mat.raw_ore`参考价3两，10个的固定官评V=30两；卖方标整单P=100两。挂牌时已付`ceil(0.005×100)=1`两，本文从挂牌成功之后开始，不再扣第二遍挂牌费。成交税=`ceil(0.05×100+0.50×max(0,100−3×30))=10`两，卖方实收90两。双方不同账号，库存容量与未绑来源均合法。

| 对象 | 请求前的已提交状态 | 本次完整提交后 |
|---|---|---|
| buyer角色 | revision10/controlRevision4 | revision11/controlRevision5 |
| buyer钱包 | silverMinor="10000"，尾数0 | "0"，尾数0 |
| seller角色 | revision20/controlRevision7 | revision21/controlRevision8 |
| seller钱包 | "0"，尾数0（已支付挂牌费后的余额） | "9000"，尾数0 |
| 原矿未绑分量 | listing托管10，买家0，卖家可用0 | listing托管0，买家可用10，卖家可用0 |
| listing | revision1/active，P100/V30 | revision2/sold、buyer与saleCommitId已记 |
| sink与系统收入统计 | 本次成交税0 | 税1000分；不增加买卖双方“系统新发收入” |
| 业务记录/回执/outbox | 无本次成交 | 同commit写terminalSale、request回执及双方个人事件 |

### 3.1 请求与报价

报价先展示P、税、买家实际支付、标的10个未绑原矿和版本；不扣资源。服务器已签发`quote.fixture.1`并绑定该角色、挂单版本和期限。请求只包含意图，不接受客户端回传的P、卖方收入、原矿归属或税作为权威。

  "saveEpoch": "epoch.fixture.1",
  "characterId": "char.fixture.buyer",

      "kind": "listing",

写者先查原requestId历史，再按M0沿用的顺序独立持久处理时间前置事务，之后锁挂单/买卖双方钱包与材料归属并校验最新角色版本；seller的私有版本不要求买家知道。本例假定前置事务没有改变列出的余额/版本，若有则先更新请求前切点，不能抄用表中版本。检查quote未到期、listing仍active、F16材料市场已启用、钱与容量足够后，仅在工作副本产生表中after-images。

### 3.3 故障前后必须只有这两套账

| 故障/重试位置 | 允许恢复的账 | 不允许出现 |
|---|---|---|
| 工作副本算完，日志尚未持久 | 全部请求前状态；未给成功 | 只扣买家、卖家/物品没动 |
| 有完整持久帧，HTTP未到客户端 | 全部提交后状态；查原requestId得同commit | 因“客户端没收到”再扣100两 |
| 同ID同payload再次发送 | 返回同result，replayed=true | 新listing、新税、新10原矿 |
| 换requestId却仍买已sold挂单 | 已售出业务拒绝，买家0新增支出 | 旧托管再交付一次 |
| 两买家同时买 | 一人得到上述成交；另一人无扣款 | 两人各得10原矿或卖方收两次 |
| 买与撤单/到期竞争 | 一个终态获胜；另一操作读取该终态 | 成交后又返原矿给卖方 |
| 发出outbox后未标已送即崩溃 | 原eventId可再投递，钱货仍一笔 | 用消息ACK触发再发奖 |
| 30天后重放 | permanent摘要返回already_committed并引导查当前对象 | 回执过期就重新执行 |

两人钱包之和减少1000分，等于成交税；原矿总量10不变。先前挂牌费是另一笔已提交消费，不计进本次守恒式。这个确定性账例不证明市场价格合理、数据库事务可用或真实崩溃恢复已经通过。

## 4. 时间状态片段的检查方式

| 片段 | 最低字段/原状态 | 再登录/跨期后期望 |
|---|---|---|
