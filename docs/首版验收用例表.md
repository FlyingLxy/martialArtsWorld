## 1. 执行、证据与判定方式

每个主用例只有在其全部必需参数单元有执行记录时才能关闭。记录键为`AC-xx/参数单元`，另存执行者、复核者、时间、代码提交、manifest/schema/economy/combat/math版本、worldId/saveEpoch、设备/浏览器与证据位置。没有真实值时留“未执行”，不能填虚构版本、通过截图或随机种子摘要。

| fixture类别 | 可以证明什么 | 不可以证明什么 |
|---|---|---|
| **REG：正式内容配置核对** | 实际发布manifest、有限ID、前置/池/引用/预算及功能开关一致 | 配置有行不证明技能能施放、玩家能取得或接口已实现 |
| **ISO：隔离规则夹具＋完整服务链** | 在独立测试世界设置已记录的合法/边界状态，再经真实UI→鉴权→命令→事务→持久化→SSE/重登核对；允许测试时钟与预先固定随机分支 | 不能用调试发钱/材料、直接满级、缩短周界或替换背包证明真实成长、自然产量、长期平衡或游玩时长 |
| **LIVE：真实成长记录** | 新号按正常价格/规则/时间取得等级、任务、技能、装备、材料与关系，保存来源链和未剪辑关键操作 | 不允许直接发XP/物品、改余额/掉率、跳主线、加快计时、强制概率成功或绕过正式来源；一次好运不代表平均供给 |
| **UX：真实交互计时** | 使用完成的真实服务与发布内容，控制起点并标明其来自ISO或LIVE；人在实际设备上阅读、导航、输入、确认与恢复 | ISO准备起点不证明它自然可达；不能用演示录像、预背答案、自动点按或测试快捷键代替首次玩家实测 |
| **FAULT：独立副本故障演练** | 实际写路径在规定时点断进程/损坏副本/恢复备份后的行为 | 不操作生产玩家数据；不把正常重启或mock返回成功当成故障已覆盖 |

ISO也必须经过实际服务与持久链，不能只直接调用一个函数后比较内存。操作前保存可恢复基线；负例只在隔离环境注入。随机分支固定只用于验证该分支的支付/结算，概率分布和战斗平衡另做有版本、样本量、区间和失败报告的验证，不能以“固定种子打赢”代替平衡结论。

| 证据代码 | 每次实际执行要保留的内容 |
|---|---|
| **UI** | 含起点、动作、结果/错误和恢复的录像或连续截图；记录视口、缩放、输入方式；不得只截“成功” |
| **NET** | 脱敏请求/回执/相关SSE帧：requestId、payloadHash引用、commitId、revision/controlRevision、对象版本、事件游标；删除凭据与非必要私信 |
| **LED** | 同切点前后钱包/精确尾数、材料分量、uid位置/锁、资格/进度、业务唯一键、账本、相关outbox；记录守恒差额，不能只看UI余额 |
| **TIME** | 服务端时间/区间/period、lease与结算锚点、操作计时标注；区分serverTime、committedAt与视频时钟 |
| **CFG** | 实际有限ID清单、规则/模板版本、参数展开列表、独立公式期望与运行结果差异；避免直接复用待测函数产生“期望值” |
| **RESTORE** | 原快照/日志/备份manifest摘要、故障位置、恢复切点、被隔离对象、启动健康状态及原requestId查验 |
| **TRACE** | LIVE角色从创建至目标的实际来源/支出/任务/成长记录；每次外部测试干预须标记，受干预段不能作自然成长证据 |

证据目录建议为`evidence/<build>/<AC-xx>/<参数单元>/`，这是未来测试产物目录，不是本轮已生成文件。记录实际故障、失败和缺失证据；隐去敏感数据不应删掉用于对账的稳定测试身份引用。

**阻塞级别：**P0表示资产/权限/恢复错误、保留范围缺失或核心流程无法完成；P1表示主要呈现、性能或体验指标未达到。P0/P1均阻塞对应M阶段出口及正式发布；需要修复，或经明确评审调整目标、写回原合同后复验，不能未关闭就放行。未执行、失败、配置缺失和范围待决定都不能记通过。条件性D项未启用时验其关闭态；这不能代替其保留依赖已补齐，也不能擅自把F15等首发承诺改成“可跳过”。

## 10. 耗时测量与未定性能预算

AC-66本轮建议最低20个计时单元：`5份/15份 × 桌面/手机 × 每格5名参与者`。每格建议至少3名首次读该题、2名已有同类经验；不能把同一人背完桌面答案后当手机“首次”。不把参与人数或结果承诺为统计认证。为了不把一时好运当通路，每个单元记录选择的实际DQ列表、导航距离、错误类型及每份资格ID；同时复核28定义的AC-24，不只抽最快的一题。

日常计时从玩家开始处理待办到最后一次奖励已提交并可见结束，分项记录：读任务/规则、接取、导航、判断/输入、必要等待、错误定位/改正、确认/领取/恢复。主动时间包括需要持续注意的决策、阅读和必须操作，不把动画期间必须看懂的提示或服务端慢响应一概划成“挂机”；纯无人操作值守另计。五份值守30分钟、十五份90分钟的自然等待必须如实显示。分别报告主动、等待、总时长、中位数和最大值；样本少时不凭一个P90数声称全体玩家达标。任何有效标准样本主动超过900秒，都保留失败并回到设计；复验覆盖同样的困难路径。

AC-67建议最低30单元：`浅探/深入/绝境 × 桌面/手机 × 每格5人`。计时起点是实际入局扣次，终点是三层成功结算已提交并可查看，不在最后一刀动画前停表；准备与5选2、节点选择、补给、实际服务等待均在总时长。原合同目标为主动操作约15分钟，本轮建议以主动≤900秒作为首轮检查线；未另定总墙钟上限。需要持续注意的阅读、决策、反馈和恢复均计主动，纯自动战斗/后台等待单列；另记录战斗/动画秒、服务等待、长暂停；正常样本不能用提前熟悉种子、跳动画测试指令或短失败局替代。外部故障/玩家长暂停样本保留原因、另列恢复验证，不偷偷剔除慢战斗或难选择。若普通可达构筑无法通关，还须先登记构筑/供给阻塞，不仅报一个很短的失败耗时。
