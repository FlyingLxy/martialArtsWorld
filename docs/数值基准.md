# 数值基准

> 这一篇解决的问题：**v2 的所有数值从哪来。**
>
> 目标是能随时回答「20 级该拿多大的刀」「新加的怪配多少血」，
> 并保证装备、怪物、收益三条曲线长在同一根轴上。

## 一、为什么需要这一层：v1 的证据

v1 的数值是各自手填的，实测下来：

```
武器攻击倍率   2.75 → 2.00 → 1.73 → 1.74 → 1.67 → 1.55    递减但不规则
武器价格倍率   6.00 → 3.89 → 3.14 → 3.64 → 3.75 → 3.00    忽高忽低
怪物血攻比     6.7 → 6.4 → 6.9 → 8.8 → 9.7                 越往后越肉
```

血攻比飘动意味着**不同等级段的战斗节奏不一样**——低级几下打完、高级要磨很久，
这不是设计出来的，是填出来的。

**v2 不重复这个。** 下面的做法就是为了让这类问题在加数值的当下就暴露，
而不是上线后靠手感发现。

## 二、做法：一条基准曲线，万物从它推导

行业里数值策划的标准做法：**先定"标准玩家"在每个等级的样子**，
其余一切（装备、怪物、收益、价格）都是它的函数。

```js
// gamedata/baseline.js —— 唯一的真值来源
const BASE = {
  // ① 标准玩家：某等级"正常成长"的角色应该有多强
  atk : lv => …,     // 含装备
  hp  : lv => …,
  def : lv => …,

  // ② 装备占战力的比重（设计决策，不是拍脑袋）
  weaponShare : 0.40,   // 武器贡献四成攻击
  armorShare  : 0.35,   // 护体贡献三成五防御

  // ③ 战斗节奏（用"几回合分胜负"来定义，而不是直接填血量）
  roundsToKillMob    : 6,    // 打同级怪要六回合
  roundsToBeKilled   : 15,   // 同级怪打死你要十五回合
};
```

于是：

| 要定什么 | 从基准推 |
|---|---|
| N 级武器的攻击 | `BASE.atk(N) × weaponShare` |
| N 级怪的血量 | `BASE.atk(N) × roundsToKillMob` |
| N 级怪的攻击 | `BASE.hp(N) ÷ roundsToBeKilled` |
| N 级装备的价格 | 由该等级段的**收入速率**推——比如"三小时的收入" |
| 场景的泡点收益 | 由[经济与成本](经济与成本.md)的升级曲线倒推 |

**好处有三层**：

1. **加东西有依据。** 想加一把 45 级的刀？`BASE.atk(45) × 0.4` 算出来就是。
   不用再猜"170 是不是太高了"。
2. **改节奏只改一处。** 觉得战斗太拖沓？把 `roundsToKillMob` 从 6 改成 4，
   所有怪的血量自动跟着变，不用手改几十条。
3. **各系统天然一致。** 装备曲线、怪物曲线、收益曲线都长在同一根轴上，
   不会出现"这一段装备太强、那一段怪太肉"。

## 二之一、基准曲线的形状：三种跑法对比（建议分段）

参数都调到 60 级总成长 ×33 左右，只比形状。

### 每升一级，感觉强了多少

| | lv5→6 | lv30→31 | lv59→60 |
|---|---|---|---|
| 线性 | 16.7% | 3.2% | **1.7%** |
| 指数 | 6.1% | 6.1% | 6.1% |
| **分段** | 7.5% | 6.0% | 4.5% |

**线性直接出局。** 后期升一级只强 1.7%，玩家根本感觉不到——
对一个以升级为核心驱动的挂机游戏，这是致命的。
前期 16.7% 也太陡，几级之间断层。

### 两个朋友差 5 级，还能不能一起玩

| | lv10 vs 15 | lv30 vs 35 | lv55 vs 60 |
|---|---|---|---|
| 线性 | ×1.45 | ×1.16 | ×1.09 |
| 指数 | ×1.34 | ×1.34 | ×1.34 |
| **分段** | ×1.44 | ×1.34 | **×1.25** |

判断标准：**×1.3 以内还能一起打**（弱的有存在感）、
×1.5 以上弱的是拖油瓶、×2 以上只能被带。

**这一栏是为我们这种局专门看的。** 十来个朋友，等级必然参差不齐，
到了后期如果差 5 级就打不到一块去，人就散了。
分段在 lv55 段是 ×1.25，落在"还能一起打"里；指数恒定 ×1.34 已经偏高。

### 建议：分段

```
lv 1~20    每级 +7.5%     新人前几级升得爽，留存最关键的时候
lv 21~45   每级 +6.0%     主体节奏
lv 46~60   每级 +4.5%     差距收敛，为满级横向做准备
```

三个理由：

1. **前期陡，后期缓，正好对上留存曲线。** 新人最需要"我在变强"的反馈，
   老玩家更在乎横向内容。
2. **接近满级时等级差变得不重要**，朋友之间不会因为差几级就没法一起玩。
   这跟"[60 级是分水岭、满级后横向](地图系统.md)"的定位是同一件事。
3. **跟装备占比天然咬合。** 后期等级给的收益变小，装备占比就自然抬上去了，
   不用额外掰——正好落到满级 65% 那个数。

**一个副作用要留意**：20 级和 45 级两处有斜率突变，
细心的玩家会察觉"升级变慢了"。若介意，可把三档改成连续递减的函数，
形状一样、没有台阶，代价是不如分段直观、也不好口头描述。
**建议先用分段**，真有人抱怨再平滑。

> 注意这条曲线是**属性成长**，跟经验需求曲线（`60·lv^2.2+40lv`）是两回事，
> 一个管"每级强多少"，一个管"每级要多久"。

## 二之二、可持续投入的系统：用阶梯，别用线性

这一节讲**方法**，不给具体数字——打造、天赋深度、声望档位、家园等级
这类"可以一直投入"的系统，v2 都要重新设计，数值等各自的设计文档定。

### 要避开的形状

```
收益线性  +  成本指数   →   边际效用断崖
```

每一级提升都一样多，而成本和风险一路飙升，**理性玩家会在某个点停下**，
后面的内容等于没做。这是[原则第九条](原则.md)要防的东西。

### 该用的形状：阶梯递增

把投入分成几个档，**越往后每一级涨得越多**：

```
低档   小幅提升，便宜、稳，人人都能到      —— 让所有人尝到甜头
中档   中幅提升，开始要成本和运气          —— 大部分人停在这
高档   大幅提升，昂贵且有风险              —— 少数人的军备竞赛
```

**关键技巧：让每个阶梯的起点成为效率甜点。** 也就是跨进新档的第一级，
"每点属性花的钱"要比上一档最后一级**更低**。这样玩家在档位边界上
不是被劝退，而是被拉进去——"再冲一级就进新档了"。

用「每 1 点提升的实际成本」这条曲线来检验：它应该是**锯齿上升**
（每个阶梯起点回落一下），而不是一路陡峭爬升。

### 概率要有四档，不是两档

按[原则第八条](原则.md)，同一次投入应当有惊喜也有事故：

| 结果 | 效果 | 作用 |
|---|---|---|
| **大成功** | 一次跨两级 | **这是玩家会讲给别人听的事** |
| 成功 | 正常前进 | 主流结果 |
| 失败 | 原地不动，或高档时倒退 | 成本的来源 |
| **大失败** | 倒退两级（只在最高档存在） | 让高档真正有分量 |

**建议加隐性怜悯**：连续失败若干次后，悄悄提高成功率。
但别做成明面保底——保底一公布，玩家就开始数次数，随机的戏剧性立刻消失。

## 二之三、四维属性（已定）

天赋文档引用了"角色四维属性"，但全文只出现过「身法」「悟性」两个，
另外两维从没列全。而且**「悟性」这个词说不清它管什么**——
是内力？是技能伤害？还是暴击？玩家看到它不知道该不该加。

好属性名的标准只有一条：**看名字就知道加了会变强在哪。**

### 三套经典的参照

| | 属性 | 加点 | 成就 | 栽在哪 |
|---|---|---|---|---|
| **暗黑2** | 力量／敏捷／体力／精力 | 自由 | 四维自由分配，build 深度高 | 力量退化成"够穿装备就行"，精力是公认陷阱属性——**四维实际只用了两维** |
| **梦幻／大话** | 体质／魔力／力量／耐力／敏捷 | 每级 5 点 | **回合制的标准答案**：敏捷决定出手顺序，这一维永远不会废；体质血、耐力防分开 | 加错点角色就废，洗点极贵——新手得先查攻略才敢升级 |
| **魔兽** | 力量／敏捷／耐力／智力／精神 | **不给加点** | 主属性按职业自动给，彻底消灭"加错毁号"；深度全放进天赋树和副属性配装 | 升级时少一份参与感 |

**我们是回合制，梦幻／大话最对口。** 但它那个坑不能踩——
我们已经有[180 个节点的天赋树](talent-system.md)承担 build 深度了，
**属性点不该是第二个"加错就废"的陷阱**，那是双重惩罚。

### 提案：四维 + 副属性两层

沿用四维不扩到五维（体质／耐力分家对文字游戏太细），命名取武侠说法：

| 主属性 | 对应 | 主要影响 | 谁会主加 |
|---|---|---|---|
| **力道** | 力量 | 攻击、外功伤害 | 外功输出 |
| **身法** | 敏捷 | **出手顺序**、闪避、命中、暴击率 | 灵巧流、暴击流 |
| **根骨** | 体质 | 气血上限、防御 | 坦、生存流 |
| **元息** | 精力／魔力 | 内力上限、内功伤害、冷却缩减 | 内功输出、高频施法 |

**身法管出手顺序——这是抄梦幻抄得最值的一条。** 回合制里先手就是一切，
这一维因此永远不可能变成废维，暗黑那个坑自动躲开了。
暴击也挂身法，跟"敏捷角色出手刁钻"的直觉一致，
接上[装备与打造](装备与打造.md)里"暴击是人物属性、装备只是主要来源"。

**副属性**（暴击率、暴击伤害、命中、闪避、冷却缩减）走魔兽路线：
不直接加点，**主要来自装备和天赋**。这样配装才有嚼头，
也让"打造"和"凑套装"有了明确的收益方向。

**「元息」这个词来自[世界观](worldbuilding.md)第三节，不是新造的。**
四海会馆的学者用它统称天地间那种生命与精神之息——
中原叫内力真气，奥术学院叫魔力，王冠骑士团叫圣息，影之忍宗叫忍气，
北海战团叫怒气，太阳神殿叫神力。**它本来就是这些东西的统称**，
拿来当属性名是现成的。

这一点很重要：我们有十个门派，五个在海外。
「元气」是中原说法，奥术学院的人顶着「元气」条会很别扭；
而「元息」正是世界观里为跨文化交流准备的译名——
**系统级的属性名要的就是这种中立性。**

顺带一个几乎不要成本的彩蛋：**属性统一叫元息，但资源条按门派显示本名**
（中原显示"内力"、奥术显示"魔力"、北海显示"怒气"）。
机制完全不变，只换一个显示名，代入感却差很多。

天赋文档里的"每 20 点悟性使剑法伤害 +1%"平移到元息，效果不变。

### 与战斗文档的对齐检查

逐条比对过[回合制战斗](turn-based-combat.md)、[天赋](talent-system.md)、
[平衡模拟](combat-balance-simulation.md)，结果如下。

**已经对上的（不是新增，是对齐）**：

- **身法决定行动顺序**——战斗文档 3.1／3.2 早就是这么写的，
  而且比我写得细：优先级 > 身法 > 可复现随机，且回合中途获得的身法修正
  从下一回合才生效。提案跟它一致。
- **基础暴击 8%** 已存在于模拟基线（6.1）。这直接证实了
  "暴击自身来源不能是零"——裸装也会暴。
- **暴击率用「百分点」计**（天赋文档第 82 行已规定），装备词条照此书写即可。
- **力道、根骨**在同事三份文档里一次都没出现，可自由定义，无冲突。

**四维本身已定**：力道／身法／根骨／元息，副属性不加点、主要来自装备与天赋。
下面四处是实现细节，需要同事确认，不影响四维定案：

1. **「气贯长剑」的属性归属**（天赋 388 行）：现写"每 20 点悟性使**剑法**
   直接伤害提高 1%"。悟性改元息后，成了"元息提升外功剑伤"。
   但这招名字就叫**气贯长剑**——气灌进剑里，改名后反而更贴。
   建议**保留并认可**：元息主管内力与内功伤害，但**允许天赋做转化**，
   华山剑气流正好占这个设计位。需要在元息的定义里写明这一条例外。

2. **模拟基线没有装备维度**（模拟 6.1）：标准属性写死 1200／112／42／100、
   暴击 8%，这只代表**裸装**。而我们刚定满级装备占战力 65%、
   暴击主要来自装备——满装玩家暴击可能是 30%+。
   **所有现有平衡结论（含切磋 19.32 回合）只在裸装下成立。**
   而天赋里「心如磐石」（减暴伤）、「剑到人亡」（+15 百分点暴击）、
   「借势翻身」（受暴击触发）的强度都会随装备大幅漂移。
   → **模拟需要增加"满装"档位复验**，否则平衡结论在满级段失效。
   **已定：这一轮复验推迟到装备数值填完之后再跑**，
   但它是[装备上线的硬关卡](落地顺序.md)，不是可选项。

3. **冷却缩减存不存在？** 元息的产出之一是冷却缩减，但战斗文档第 6 节
   只写了冷却的登记与推进，没有缩减机制。如果不支持，
   元息就少了三分之一的产出，需要换一个（比如内功穿防）。

4. **命中会不会溢出？** 基础命中 95%，天赋里"命中"出现 95 次是绝对主力，
   现在装备词条和身法又都给命中——很容易叠过 100% 变成废属性。
   需要一条上限规则（超出部分转成别的，或对高闪避目标才生效）。

### 三条配套（都是别人踩过的坑）

1. **洗点必须便宜。** 深度在天赋树里，属性点只是风格微调，
   没道理让人查攻略才敢升级。建议低等级免费、满级后收少量银两。
2. **逐维回答"谁会把点主要加在这一维"**（上表最后一列就是这个检验）。
   答不上来的就是废维，要么改产出，要么砍成三维。
3. **不做"穿这件要 50 力道"的门槛型需求。**
   正是它把暗黑的力量从"越高越强"退化成"够用就行"。

## 三、但别做过头

**不是所有数值都该公式化。** 有两类要留手工：

- **有性格的东西**：金钟罩为什么是减伤五成而不是四成？
  这是玩法设计，不是数值推导。武功效果、场景机制、任务奖励类型都属于此类。
- **故意的破格**：某把武器就是要比曲线强一截，作为稀有掉落的惊喜。
  **但破格要标注出来**（比如写 `off_curve: true`），
  免得下次有人"顺手把它拉回曲线"。

判断标准：**问"这个数改了会不会影响别的数"**。会的（装备强度、怪物血量、
收益速率）就该公式化；不会的（技能倍率、文案、掉落种类）留给手工。

## 四、配套：校验与模拟

光有曲线不够，还要能**验证**。这两样跟公式同等重要：

**① 校验脚本**（类似已有的 `gamedata/check.js`）

```
检查每件装备是否在曲线的 ±15% 内（超出必须标 off_curve）
检查每只怪的血攻比是否落在设计区间
检查每个场景的泡点收益是否符合等级段
```

新加内容时跑一遍，**越界立刻报**，而不是上线后靠玩家发现。

**② 模拟**

同事的[战斗平衡模拟](combat-balance-simulation.md)已经在做战斗侧。
数值侧同样需要：给定一条"标准成长路线"，跑完整个 1→60，
输出每个等级段的**升级时长、战斗时长、金币结余**，看有没有断崖或者飙升。

## 五、跟别的文档怎么分工

| 文档 | 管什么 | 边界 |
|---|---|---|
| [战斗平衡模拟](combat-balance-simulation.md) | **十派之间平不平衡**（相对值） | 角色属性写死 `maxHp:1200 atk:112 def:42`，刻意简化以排除干扰 |
| **本文** | **每级该有多少数值**（绝对值） | 装备、怪物、泡点收益、价格 —— 这些模拟脚本里一次都没出现 |
| [经济与成本](经济与成本.md) | 产出与回收的**比例政策** | 经济是政策，基准是执行 |
| [地图系统](地图系统.md) | 场景的**性格** | 场景的泡点收益由本文曲线推导，不各写各的 |

### 与平衡模拟的接口

同事的 `npm run balance:v0.5` 已经跑通：750 种构筑、28 万场对战，
十派胜率收在 **47.9% ~ 52.0%**，180 个天赋全部触发。**这是相对平衡的验证。**

但它只验了**一个切面**——所有角色都是 1200 血 / 112 攻 / 42 防。
本文的基准曲线正好补上另一半：

```
本文输出            BASE.hp(lv)、BASE.atk(lv)、BASE.def(lv)
模拟脚本消费         把写死的 1200/112/42 换成按等级取值
于是能回答           "10 级、30 级、60 级时，十派是不是同样平衡？"
```

现在的模拟无法回答这个问题——比如某个门派的天赋是"按最大生命值百分比回血"，
它在 1200 血时平衡，到 60 级 5000 血时可能就超模了。**分段验证需要基准曲线做输入。**

**建议的对接方式**：基准曲线定稿后，在 `simulate-v0.5.js` 里把那三个常量
改成从基准取值，并按 10 / 30 / 60 三个等级各跑一遍。

## 待拍板

0. **装备与打造体系**由各自的设计文档定（尚未开写）。本文只给形状与占比上限。
1. **战斗节奏是分布，不是定值**（建议已给）：期望值只是中心，
   **八成落在哪个区间**才是真正要定的东西。方差随难度递增：

   | 对手 | 期望回合 | 八成落在 | 最快 | 最慢 |
   |---|---|---|---|---|
   | 同级小怪 | 6 | 5 ~ 8 | 3 | 13 |
   | 精英 | 12 | 10 ~ 15 | 5 | 23 |
   | 首领 | 20 | 16 ~ 25 | 7 | 38 |

   **打小怪要稳**（刷不动就没人刷了），**打首领要有戏**（能被秒也能翻车，
   这才有故事）。被同级怪打死的期望 24 回合同理，是中心不是保证——
   连续被暴击时会更快，这正是[原则第八条](原则.md)要的东西。

   方差的来源就是暴击、闪避、技能触发、怪物技能，不需要额外掷骰子。
   **调方差的旋钮是这些概率的大小，不是回合数本身。**

2. **装备占战力：升级期和满级后是两个数**（这是上一版的错误，已改）

   | 阶段 | 装备占比 | 满打造后装备倍率 | 总战力提升 |
   |---|---|---|---|
   | 升级期（1~59） | **35 ~ 40%** | —— | 等级和天赋是主力 |
   | 满级（60） | **65%** | 约 ×3 | **约 +80%** |

   升级期装备占比低，因为等级、属性点、天赋都在涨，装备只是其中一环；
   **满级后装备是唯一还能涨的东西**，占比必须抬上去，否则打造无人问津。

   上一版写的"40% → 58%"实际只有总战力 +43%，撑不起一个要花几十万两、
   还会打碎装备的终局追求（参照魔兽：毕业装相对刚满级是 2~3 倍战力）。
   **60 级是分水岭**这个定位，在数值上就体现为装备占比的这一跳。

   65% 是**上限**，不是目标。再往上（70% = 战力翻倍）会让没打造的人
   在切磋里毫无还手之力——十来个朋友的服务器，这比数值膨胀更致命。

3. **怪物的技能与概率**：v1 的怪只会普攻，站着挨打。v2 每种怪至少要有
   一个特色行为（狼群会呼唤同伴、刺客会隐身突袭、护法会加护盾），
   这是[原则第八条](原则.md)的直接要求，也让"打什么怪"有了区别。
