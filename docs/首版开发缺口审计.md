## 3. 开工前最值得补齐的六件事

### 3.1 发布范围和依赖顺序：每个系统自己的“第一版”还没有汇成同一个版本

目前《开发里程碑》安排 M1 做四出生地 16 景，M2 做 10～30 级择承、装备、市场、天赋，M4 才做剩余场景与整条《姑存》。但 10 级择承需要洛阳，主线 18 级进入万国码头，18/26 级学艺也需要任务与对应场景。按表逐期做会发现上一期需要下一期的东西。

此外，场景卡标 49 景又建议首发 30 景；“一行门派驻地”是否拆成多个可进入场景也没有统一。推荐等级、进入等级和泡点门槛需要分别登记，不能把“码头推荐 25+”直接用成主线的进入条件。

**最小补齐：一张首版发布表。** 每项登记开放等级、地区/场景 ID、任务/技能、产出、入口、所属里程碑和验收人。将 M1 所需的新手主线与赴洛接缝、M2 所需的洛阳/码头/学艺提前；列清家园、禁地、潮汐、唯一武器等各自是否进入这一轮。

依据：[开发里程碑](开发里程碑.md)第 22～76 行；[主线任务设计](主线任务设计-姑存.md)第 57～73 行；[技能进度合同](技能进度与等级扩展合同.md)第 26～44 行；[场景卡全集](场景卡全集.md)第 204～214 行。

### 3.2 数值单一来源与四维换算：这是最早会造成返工的缺口

最新调整已经宣布旧的 `180 EP / 装备65% / +80%` 作废，当前模拟输出为约 `163.4 EP / 56.4% / +63.4%`。但正文、表格和脚本没有同步干净：

| 位置 | 目前的冲突 | 对开发的影响 |

| 《装备数值模拟报告》第 3～5、32～69 行 | 开头废弃旧方案，核心表格仍合计 180，部分公式也仍为 +80% | 文档“精确值”不能直接拿来导数据 |
| 《开发里程碑》第 15 行 | 1 级气血验收为 37；当前基准与模拟为 51 | M0 单测会验错目标 |

模拟器本身也需要补交叉检查：二/四件套仍输出 `3/7 EP`，但同一结果的 `4+2` 为约 `9.123 EP`；最高打造档每级约 9.886%，又略低于前一档的 10%，需要核对“阶梯递增”原则。这两点不会被本次通过的静态检查完整拦住。见装备模拟脚本第 76～85、578～585、712～715 行。

四维还只明确“管什么”，没有闭合初始值、每级属性点、每点换算、上限、洗点费用，以及裸身/标准装/终局各自如何生成最终属性。只写 EP 比例不能直接算出玩家的攻击与气血。

**最小补齐：以现有调整意图收口一份机器可读的基准、属性换算与上限表，数值表从它生成。** 固定 1/10/20/30/40/50/60 级样例；给出未入门散人、已入门角色和不同装备阶段的可复算结果。保留争议项，不能仅因某脚本能跑就把它自动提升为新的规则权威。

### 3.3 可执行内容表：现在有内容设计，但还不能直接导入游戏

**装备是最明显的一处。** 原工作区《装备总表》自己明确：131 是结构位，80 武器等级待定，45 防具未命名，没有已定的 1 级代表模板；永久 `templateId`、属性、词条池、Icon、来源、十套×十派武器映射均未闭合。它补了库存清单，还不是可投放数据。基础防具和等级变体补齐后，最终模板数可能超过 131。

地图、怪物、NPC、材料、证据、见闻也需要稳定 ID 和引用表。怪物目前大量是“某族系某档”，缺具体等级/技能参数/遭遇权重；普通怪、精英、稀有和首领还要明确同时点击、战斗占用、奖励归属与刷新持久化。

任务已有节点设计，但制作规格仍明确待填逐字文本、奖励值、敌人数值、保护回合、观察触发量和专用交互。40 条学艺任务已有 ID 与标题，18/26 级这两批需要先展开，不能把学技能实现成达到等级自动获得。

**最小补齐：先补首个可玩阶段会引用到的数据。** 每行至少含稳定 ID、所属版本、进入/使用条件、配置值、来源/去向和验收状态；建立引用校验，禁止 `reserve:*` 或空名字进入掉落、商店和玩家界面。全量对白、后期美术可以随内容阶段补；首批物品身份和奖励关系必须先定。

依据：[本地装备总表](/Users/liuguangfu/Desktop/martialArtsWorld/docs/装备总表.md)第 12～18、58～60、198～204 行；[主线任务设计](主线任务设计-姑存.md)第 330～337 行；[技能进度合同](技能进度与等级扩展合同.md)第 156～181 行。

### 3.4 低等级日常与跨系统经济：每个玩法的收益不能分别定

M1 要前 10 级每天 5 次日常，但现有任务样例主要依赖门派或洛阳，无门派公共日常仍有待定项。永久散人又是合法完整选择。因此需要真正能在四出生地接取、完成、交付的公共任务池。

当前已发现的经济冲突包括：

- 市场文档收上架 0.5% + 成交 5%，装备文档推荐 2% + 8%，还需统一溢价税、取整、退款和参考价。
- 市场建议“已打造可卖、打造清零”，装备文档规定“首次打造绑定、不能卖给玩家”。这会改变整个物品流转模型。
- 怪物普通成品掉率、额外词条大丰收，与装备的固定词条数、成品概率/保底尚未统一。
- 日常与门派任务是否共用 5 次池未收口；文档当前按 12+8 分钟估算已超每日 15 分钟目标，这不是 v2 已经实测完成。
- 材料等级、掉落/家园/禁地产量、打造/洗词条/分解成本和日周上限尚无贯通总表。高级材料绑定例外需要明确留在终局哪些部分。
- 打造成本主要写成 `H(L)` 小时收入，`H(L)` 本身缺各等级实际银两收入表；还缺泡点绝对收益、材料供应速率与首次装备取得时间。成本的比例闭合不等于玩家能在预期时间获得材料。

**最小补齐：统一材料与奖励账本，并定公共/门派日常的次数规则。** 每条产出写来源、频次、数量/概率、绑定、用途、回收和上限归属；按普通挂机、少量主动、集中周末游玩三种情况计算成长与余额。首次测试重点看“能否买到补给、完成日常、完成一次打造”，再推满级长期平衡。

依据：[任务系统](任务系统.md)第 32～36、82～84 行；[市场与家业](市场与家业.md)第 25～71 行；[装备系统](装备系统.md)第 1394～1417 行；[玩法与核心循环](玩法与核心循环.md)第 322～339 行。

### 3.5 状态与持久化合同：字段示意需要变成可以落盘和恢复的数据

> 第5项已形成六份合同稿，入口为[数据模型与接口](数据模型与接口.md)，含完整准备态空根、初始化片段与跨角色资源账例。以下是原审计发现，存储缺陷仍未修复；“有恢复步骤”不等于完成真实恢复验收。

《数据模型与接口》已经有方向，但仍缺以下必要细节：

- 账号与角色的稳定身份、存档版本、清档保留字段、未知内容 ID 的兜底。
- 主线/日常/学艺分槽、调查检查项、案卷和动态姓名快照、一次性奖励标记。
- 装备模板与实例 `uid`、材料唯一数量来源、物品占用/绑定状态。
- 日周次数的周期键、离线期间补发、跨 5:00/周一/重启时恰好发一次。
- 命令路径、参数、成功/失败回执、状态版本与 SSE 重新连接后的恢复。
- 交易/打造/领奖的持久化幂等记录；不能仅写“内存去重 5 分钟，重启清空”就作为贵重资产的完成保证。
- 家园队列与禁地局状态、断线恢复检查点、已扣消耗品、固定随机状态与已结算节点。

具体漂移：文档称沿用 `POST /cmd`，实际是 `/api/cmd` 与单独的 `/api/login`；现有命令即使内部失败也可能返回 `{ok:1}`。这些需要统一，前端才能区分扣费失败、已执行、等待同步和可以重试。

**当前代码另有已复现的存档缺陷，应列为 M0 必修。** 在临时目录用 `store.init → markAll/flush → 修改 gold → markPlayer/flush → close` 测试，第一次写入 10，第二次改成 99 后磁盘仍为 10，关闭后也仍为 10。`store.js:168-177` 中 JSON 同步分支先清空 `flushing`，外层赋值又放回已完成 Promise，后续写入被当成仍在执行。这与本轮主链测试的重启失败是两项独立发现。

**最小补齐：一份可序列化的首版存档样本、一条资源命令的完整请求/回执/落盘过程，以及恢复验收。** 对 20 人朋友局，不需要增加分布式服务；需要的是每次钱货变动能可靠保存、重启后不丢不重发。

依据：[数据模型与接口](数据模型与接口.md)第 11～44、104～125、149～186 行；[现有存档实现](../store.js)第 157～178 行；[现有命令接口](../server/http.js)第 85～95 行。

### 3.6 第一条体验链和验证：总布局不等于所有操作已定义

UI 已确定三栏、公共/个人信息分屏和移动端方向；仍需要一条真实新号路径，把这些东西接起来：

```text
注册与选故乡 → 泡点/聊天 → 接主线 → 调查或战斗 → 领奖
→ 10级到洛阳 → 入门或继续散人 → 学技/配装 → 退出并恢复进度
```

主线的案卷三栏、配对/叠图/计时换算，战斗资源/状态/冷却/自动出招优先级，背包满、资金不足、未满足前置和掉线恢复都需要明确界面反馈。无需先做全套精美图标，但必须能完成操作并解释失败原因。

**最小补齐：把上述链路写成验收场景，并做一个可操作样例。** 技术验证先选一个故乡和两个机制不同的门派，再按相同合同扩到四故乡十派；分别用桌面和手机窄屏验证，聊天必须始终可达。

| 攻防/械斗/机器人/深层家园社交 | 人数降级、身份标识、计数隔离与跨玩家事务定案 | 不影响第一条成长体验链 |

这里是建议的阶段划分，不是替用户变更“完整首发 60 级”的既定目标。

## 5. 推荐接下来的工作顺序

1. **收口首版发布表和冲突清单。** 明确完整 60 级首发与首次可玩内测的区别；决定哪些功能进入第一轮验收。
2. **执行 M0。** 统一数值与四维，修存档基础问题，定义稳定 ID、存档版本、时钟和资源命令；让空世界可靠启动、结算、保存、恢复。
3. **完成 1～10 级体验链。** 一条故乡主线、公共日常、少量真实怪/装备/材料、泡点聊天、失败与恢复；验证后扩四故乡。
4. **扩到 10～30 级朋友内测。** 接洛阳和码头、《姑存》至 25 级、十派择承、18/26 级学艺、六槽装备与市场；五条线各有最小展示。此为建议的内测切分点，不是新等级上限。
5. **再铺到完整 60 级发布范围。** 按发布表补后期地图、38/50 级学艺、满级装备及入选的长期玩法，每个阶段先补自己的数据与验收。

不建议此时给整个游戏凭空报工期。先用 M0 和首条链路的实际耗时，确定两位开发者的分工、内容制作量与后续排期。
