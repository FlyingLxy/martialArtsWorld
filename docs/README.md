# 设计文档 · v2

**这里是 v2 的设计，不是对 v1 的改造。**

v1 是已经跑起来的那版（根目录 [README](../README.md) 描述的），
v2 会**清档重来**，不继承它的等级、地图、任务、数值。
唯一沿用的是**泡点框架**（每 2 秒结算、场地门槛、超出衰减、挂着就涨关掉就停）。

文档里凡是提到 v1 的地方，都只有一个用途：**它是踩过的坑的证据**。
不是约束，也不是要修复的对象——v2 照着避开就行。

想清楚了再动手，先不写代码。只看未来规划时先读
[规划目标总览](规划目标总览.md)；确定第一版做哪些、先后依赖和完成标准，读
[首版范围表](首版范围表.md)，再看[开发里程碑](开发里程碑.md)。

当前处于六项开发准备的文档阶段。下表“已完成”指已有专题设计稿，不代表内容数据、功能实现或上线验收已经完成；准备进度见[补齐计划](补齐计划.md)。

第1～6项均已形成文档稿。第5项[数据模型与接口](数据模型与接口.md)补持久事务与恢复，第6项[首版体验与验收](首版体验与验收.md)及五份配套文档接上16条玩家流程、16个界面、11种状态、134条提示和80组未执行用例。当前登记共182任务、183reward、207装备、45材料、255配方事务、30来源；登记与样例文案不等于可投放内容。[M0实施基线](M0实施基线.md)现已收口12项必需决定，可以直接进入隔离v2地基实现；后期参数、D项及其余体验建议仍按各阶段处理，功能实现、平衡与真实试玩尚未进行。

## 怎么用这些文档

- 多数玩法草案末尾有「待拍板」，那是设计里还没定的岔路口。定了就把结论写回文档，别留在聊天记录里。
- 数据结构示例是给实现时参考的**形状**，不是最终代码，动手时可以调整。
- 觉得某条设计不对，**直接改文档并说明理由**——文档是活的，改文档比改代码便宜得多。
