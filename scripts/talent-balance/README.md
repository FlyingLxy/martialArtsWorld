# v0.5 天赋与技能平衡复验工具

这个目录是 v0.5 的可版本化复验资产，不是临时脚本。请保留模拟器、说明和结果快照，后续版本在新目录中迭代，不覆盖或删除本版本。

## 运行

```bash
npm run balance:v0.5
```

默认使用固定随机种子 `20260905`，每组构筑对战重复 3 次，共运行 842,625 场。快速调参可以临时降低重复数：

```bash
BALANCE_REPEATS=1 npm run balance:v0.5
```

每次运行会覆盖同版本的 [`v0.5-results.json`](v0.5-results.json)。结果中包含随机种子、重复数、文档 SHA-256、门派与构筑胜率、对局矩阵以及 180 天赋的触发计数。

## 输入与自检

- [`docs/talent-system.md`](../../docs/talent-system.md) 是 180 天赋的规则来源；模拟器会解析 10 门派 × 3 分支 × 6 节点，数量不符立即失败。
- [`docs/active-skills.md`](../../docs/active-skills.md) 是 50 门主动技能的数值来源；模拟器会反向校验技能名与基础威力，防止文档和脚本漂移。
- 每派枚举 75 个合法 10 点构筑，共 750 个；构筑数不符会终止运行。
- 所有 180 节点必须有明确的事件或类别画像；结果同时记录实际触发覆盖，未触发节点不得被视为已验证。

## 模型边界

这是设计校准模型，不是线上战斗引擎的替代品。资源、标记、护盾、盾卫、连势、残影、追加攻击等关键链路按事件执行；大量通用增伤、减伤、续航和控制节点使用“节点层级 + 事件类别”的统一画像进入估值。该处理用来对比门派底座和发现机制失衡，不能代替正式引擎中的逐条单元测试。

模型不包含隐藏门派胜率系数；调整只能落在文档明文的技能威力、资源收益、护盾或天赋数值上。
